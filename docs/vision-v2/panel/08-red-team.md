## 2. How v2 fails (probability × severity, highest first)
1. **The machine eats the company again.** ~45 new build items, most ~one session each, all harness work; "no venture work has ever run through this harness". *Job:* Job 0 freezes the integrated test as one named venture reaching Problem-validated; jobs off that path go to a dated backlog; a `harness-ratio` script puts the weekly harness-vs-venture split on the Monday page.
2. **Subscription starvation.** Nightly jobs, 3 Claude + 2 Codex lanes, reviews, continuations and the weekly loop share the founder's 5-hour window; ccusage reads local logs, not the provider meter. *Job:* runner keeps a floor for interactive use; pauses the queue above ~60% of the window or while the founder has a session open; a limit error is `blocked`, never `partial`; a `provider_mode` field makes switching to an API key a config change.
3. **Silent false success at the runner boundary.** `claude --help` (2.1.284) has no `--max-turns`; per-job `max_turns` only binds via `maxTurns` in the agent file. Schema validation checks shape, not truth; the agent's `status: done` is its say-so. *Job:* the runner decides status: a diff exists, it ran `done_test` in a clean checkout, the schema passes; it ignores reported status. Nightly canaries (empty stdout, failing test, no diff) must come back `unresolved`.
4. **The harness is silently missing in workers** (C4 flags, `--bare`, or plugin harness overridden by stale per-repo copies — 16 of 26 `~/VibeCoding` directories have a `.claude/`; the 11 shims exist because stale copies overrode agents). *Job:* preflight — a hook writes a one-time token on the first tool call; the runner rejects any result without it and checks agent-file hashes against the plugin version.
5. **Approval fatigue.** Approvals proposed for outbound, spend, publishing, refunds, money moves, legal docs, improvement proposals, trust promotions, pivot/kill, cost split, tool kill list, held support replies — times ventures. Unedited approvals make 4's founder signal noise. *Job:* hard daily cap on decisions; requests expire to "refuse"; approvals without edits are not positive labels.
6. **Untrusted input, secrets and an outbound channel in one job on the founder's Mac.** The runner runs outside the sandbox; CLAUDE.md says the sandbox guards against accidents, not containment. *Job:* three envelope flags (`untrusted_input`, `secrets`, `external_send`); the queue refuses any job with all three; 1Password CLI never in a worker environment; no chat front door yet.
7. **Runaway continuations.** Turn cap → `partial` → auto-queued continuation, nothing stops the loop. *Job:* ≤2 continuations then `blocked` into the inbox; a token budget per chain; a breaker if >30% of a day's jobs end partial/unresolved.
8. **Context overflow.** `CLAUDE.md` is 69,338 bytes (checked), loaded into every worker. *Job:* 4's 8 KB CI cap is the first build job; `runner status --brief` stays <2 KB and quotes the runner's own tallies verbatim.
9. **Action for the wrong venture.** One Mac, one identity, shared tools. *Job:* every job carries `venture_id`; credentials from a per-venture env file; the integrated test includes a seeded cross-venture read.
10. **CLI churn and single-Mac disaster.** `consume-dispatch.ts` measured against claude 2.1.246; 2.1.284 installed now. *Job:* pin CLI version, auto-update off; nightly CLI contract check (flags exist, `--json-schema` round-trips, `codex exec` returns non-empty output); back up the runner DB and call transcripts; `runner stop --all` kill switch.
11. **The second model family never lands.** Codex bug #19945 makes irreversible-tier items `unresolved`; they get waived; review is single-family again (commit b768dcf, "merged under founder-waived reduced gate"). *Job:* a pseudo-terminal wrapper plus a test that a diff with a known defect returns a non-empty FAIL.
12. **Integration hell at the end** if NN5 is read as "nothing runs until the end". *Job:* thin end-to-end path first — job 1 runs one real job end to end; later jobs widen it. The final integrated test is unchanged.

## 4. What the whole panel missed
1. **Onboarding existing repos.** `~/VibeCoding`: 26 directories, 19 git repos; 16 have a `.claude/`; 8 carry a near-identical 9.4 KB template `CLAUDE.md`. Nobody says how stale harness copies reconcile, plugin vs project precedence, or how each repo gets a ledger. *Job:* a `fleet-census` table (last commit, drift from harness, ledger present, proposed category).
2. **Migration collides with the gate.** v2 jobs edit agent files, hooks and workflows — irreversible tier (2-of-3 multi-judge + founder sign-off per PR). NN5 vs NN6 conflict unnamed. Also inherited: the builder/designer worktree contradiction, 3 unresolvable judge claims, the accepted-risk exit on 2026-11-17, `enforce_admins=false`.
3. **The integrated test is undefined** — no scenario, frozen criteria, grader or replay. Needs a replayable fixture run seeded with each failure class (empty output, turn cap, injection, cross-venture read, limit hit, flag drift) plus the live venture milestone as final acceptance; criteria frozen by a different model family (AD-018); "verified" means the runner computed it.
4. **Provider exit.** Codex is review-only, so a Claude throttle, terms change or ban stops building for every venture. A retired model name already broke a blocking lint once (2026-08-20). Needs one engines→models file and a named degraded mode.
5. **Founder hours, added up.** Monday page, daily inbox, Friday review, weekly retro, monthly items ≈ 2.8 h/week; plus 10 calls/week at ~1.25 h each with prep ≈ **15–16 h/week before supervising the v2 build.**
6. **Disaster cases.** Losing the provider account, a secret leaked in one of 19 repos, losing the Mac with personal data (transcripts, books), founder incapacity. No kill switch.
7. **Client and NDA work** through consumer subscriptions — provider data-use terms; AGPL tools touching client deliverables.
8. **This red team is single-family.** Codex was offered for role 8 and not used.
