# DR — B1-09a measurement pass: process control on darwin (2026-10-03)

**Job:** B1-09a, "Runner: admission, capacity/wall/idle backstops, pgid kill". Acceptance: "Daemon killed
mid-job → reconciled, no orphan".
**Why this exists:** speed rule 2 (DR-BUILD-SPEED-2026-10-03). The job wraps real process control, so the
behaviour was measured before the done-tests were frozen.
**Conditions:** Darwin 25.5.0 (xnu-12377.121.10, arm64), Go 1.27.1. A throwaway `HOME`, with no model turn
and no network. The workers were `/bin/sh` (bash 3.2 on macOS), `sleep`, `/usr/bin/perl` (POSIX::setsid,
because macOS has no `setsid` command) and Go programs. Neither claude nor codex was run. Everything ran
under the armed Claude Code sandbox unless a row says otherwise.

## Results

| # | What | Result |
|---|------|--------|
| M1 | `Setpgid` leader with a child `sleep` and a grandchild that calls `setsid()`, then `kill(-pgid, SIGKILL)` | The leader and child die, and **the setsid grandchild survives**. It has its own session and pgid. A pgid kill alone leaves an orphan. |
| M2 | Freeze-and-walk: `SIGSTOP -pgid`, find descendants by ppid, then SIGKILL all, using `/bin/ps` | **`/bin/ps` is refused under the sandbox** (`fork/exec /bin/ps: operation not permitted`). The first run swallowed that error and returned empty output, which looked like "no children". The walk found 1 pid, and the setsid grandchild survived. **Never shell out to `ps` in the Kernel or in tests.** |
| M2b | The same listing through `sysctl kern.proc.all` (`golang.org/x/sys/unix.SysctlKinfoProcSlice`, v0.48.0, already in go.sum and ALLOWED_MODULES) | It works sandboxed: 889 entries, each with pid, ppid, pgid and start time (µs). The setsid grandchild shows `pgid` = its own pid and `ppid` = its live parent, so **a ppid walk finds it while its parent lives.** `kern.proc.pid` looks up one pid. |
| M3 | Daemon SIGKILLed mid-job. The worker was in its own pgid, started by the daemon. | **All 3 worker processes survive the daemon's death**, reparented to launchd. Their pgid is intact and the leader's children are still under it. A restart can find the tree from a persisted `(pid, start time)` of the leader. The start time is the pid-reuse guard. |
| M4 | `exec /dev/fd/N` as a stand-in for `fexecve` | **EACCES** for both a script and `/bin/echo`. darwin has no fexecve path, so "hash and exec the same open file" cannot be done literally here. |
| M5 | TOCTOU. A swapper renames good and bad bytes over the path in a loop. 300 runs each. | **Hash the path, then exec the path: the bad bytes ran after a passing check in 71 of 300 runs** (144 were refused). **Hash while copying into a private 0700 dir, then exec the copy: 0 of 300** (143 refused). |
| M5b | Copy-then-exec of an Apple platform binary (`cp /usr/bin/env`, then exec the copy) | **The copy is SIGKILLed at exec (exit 137)**: code signing kills it on arm64. Copied shell scripts and ad-hoc-signed Go binaries run. Unmeasured: a Developer-ID-signed binary such as the claude native binary. Measuring it would mean running claude, which the brief forbids. |
| M6a | `time.AfterFunc` precision for 50 ms, 200 ms and 1 s | It fires +0.6 ms, +1.0 ms and +1.0 ms late. Timer slop does not threaten the 90% / 100% split. |
| M6b | `SIGINT` to `-pgid` of `sh` with background jobs | **Nothing dies.** A non-interactive sh ignores SIGINT for its async children, and sh itself keeps waiting. The 90% SIGINT is advisory. The 100% SIGKILL is the backstop. |
| M6c | A stdout pipe after the leader's group is killed while a setsid escapee holds the write end | **EOF arrives only when the escapee dies** (506 ms later, when the measurement killed it). A held-open stdout after the leader is reaped is a reliable *detector* of a surviving descendant. It is not an *identifier*. |

## What follows for the implementation (constraints, not method)

1. **"Kill the pgid" is not enough.** A kill must also cover every descendant found by ppid (M1, M2b). That
   includes descendants that left the group with `setsid`.
2. **Snapshot before the SIGINT stage.** SIGINT at 90% can kill an intermediate process with the default
   action. Its setsid child is then reparented to launchd and can no longer be found by ppid. The
   done-tests' tree uses exactly this shape: the leader traps SIGINT, and the middle process dies on it.
3. **A double-fork escape is out of reach.** If the intermediate exits on its own before any snapshot, the
   setsid grandchild has ppid 1 and a foreign pgid. Nothing on darwin identifies it without a per-venture
   Unix user (B1-10) or an inherited marker. M6c can detect that it exists. This is founder question 2.
4. **The same hazard exists after daemon death.** With the daemon gone, the worker's stdout reader is gone.
   The worker's next write gets SIGPIPE. If the leader dies before the restart, its setsid descendants are
   orphaned beyond the ppid walk. Persisting the descendant set periodically (pid + start time) narrows the
   window. Only B1-10 closes it.
5. **The pid-reuse guard is the start time** from `kern.proc.pid`, persisted with the pid.
6. **Exec verification:** with no fexecve, copy-then-exec is the measured way to close the TOCTOU window.
   Founder question 1 records its costs: platform binaries die (M5b), and a launcher that resolves files
   beside itself breaks.
