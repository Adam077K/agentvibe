## 1. Boundary, identity and responsibilities

**SPECIFICATION.** S1-C01 owns endorsed ends, responsibility and legitimate deciding domains. C02 owns admitted Cases, executable WorkOrders, scheduling, workflow cursors, delegated scope and total causal allowance. C03 produces staged artifacts and attributable reports. C05 supplies permitted context and current validity; C06 independently accepts the specified outcome. C04 alone controls consequences, and C08 owns independent recovery. C07 provides actual competent human/service performance; C09 presents current permission-filtered state. A workflow, skill, model or temporary worker cannot acquire any of these authorities by containing instructions to do so.

**SPECIFICATION.** All records use canonical `RecordEnvelope`, exact `Ref`, UTC timestamps, `Position`, resource quantities and kernel command results. `accepted` requires a committed, independently witnessed transition. It is distinct from output acceptance, effect observation, customer acceptance and duty discharge. Witness outage permits only existing admitted local computation within its surviving lease/context/allowance and the kernel's explicitly local `StageRef` save/export route. A StageRef is not a Ref, and importing it revalidates current restrictions. This document does not create another durability or receipt protocol.

**SPECIFICATION.** The machine file distinguishes canonical extensions, domain records and derived projections. Task is canonical `WorkOrder`; agent output is `AttemptReport`; Handoff uses `Continuation` plus accepted responsibility transfer; artifacts, claims, decisions and grants retain their canonical types. The prose labels “worker done,” “step done,” and “project complete” must always resolve to a named acceptance scope. No writable aggregate flag may override its underlying judgments or surviving obligations.

**DESIGN PROPOSAL.** Planned implementation is in the existing modular Node/TypeScript application, with protected PostgreSQL command/timer/inbox/outbox transactions. Proposed paths in the machine file are a build map, not existing modules. C03 executors remain outside protected credentials and writable registry state. Routine methods can share code and process boundaries where the kernel permits; there is no roster of permanent domain personas.

**SPECIFICATION — the layer contract, and it is new in WORK-1.1.** This chapter's rules are organised in **five layers**, each deciding a different question, with a **fixed precedence: the lower-numbered layer governs when two disagree** ([selection record](../F2/05-selection-record.md) §1 and §5.1, rules R-L1…R-L5). **L1 · consequence class** decides who may act; **L2 · a declared procedure** decides how the work runs and what each step may see; **L3 · typed standing interests** decide when work becomes due; **L4 · an `ExistenceJustification`** decides whether a worker may be created at all; **L5 · a standing holder** is the one party that exists for a duty outliving the case carrying it. Precedence is operative, not decorative: class may **raise** what a procedure permits and never lower it; an interest may arm but never admit above its effect class; an existence record may refuse a worker the class would permit but never create one the class forbids; and a holder may hold but never act. §11 states L1 and this precedence normatively; §12 states L5; §§2–8 carry L2, L3 and L4 in the sections that already own their subject matter. **No fixed boundary of [`02-architecture-selection.md`](../02-architecture-selection.md) §3 is reopened, no seventh routing class is added and no record is renamed** — that is why the architecture version moves S1.0 → S1.1 rather than S2.0.

**SPECIFICATION.** The consequence class of an action is **computed from records the acting party cannot author**: the resolved parameters, the destination and egress identity, the selector closure over conflict claims / deletion scopes / open obligations, and the owning capability contract's declared floor. The derivation returns **the set of routing classes the action reaches**, and **every reached class's gates apply**. This restates [`02-authority-recovery.md`](02-authority-recovery.md) §4 — *"Routing classes are predicates, not a total privilege rank"* and *"An action may satisfy multiple classes and must meet all their gates"* — and changes nothing in it. **No total rank, ordering or severity score is computed from the set** (R-D22, closing AT-M4-02, which observed that a rank drops C2's human requirement on an action that is both C2 and C3). A tool's self-description and the text of a command are not inputs to the derivation; a boundary is real only if what is checked at the effect is what was granted (R4 F1, carried as R-X01's premise).

**SPECIFICATION.** **An executor's grant scope is a proposal right; C04 performs every release** (R-X01, closing AT-M1-04). An executor may narrow what it asks for and may never widen what it holds, and the ability to propose a scope is never the ability to release under it. This is the only statement of that rule in this chapter; §11's release column is where it binds.

## 2. Intent, scopes, dependencies and admission

**SPECIFICATION.** `Goal` identifies a beneficiary, measurable or explicitly qualitative outcome, exact IntentVersion, success evidence, exclusions, horizon, sponsor and review/reopen rule. A goal may exist without admitted work. C01 endorses its interpretation; C02 references it from `Case.outcome_ref`. The smallest useful WorkOrder is one independently inspectable result or discriminating observation with a finite budget and an acceptance owner. It can be a one-function repair, an actual supplier confirmation or a research conclusion; a token, arbitrary hour or persona conversation is not inherently useful work.

**SPECIFICATION.** `Mission` groups goals around a bounded company purpose and review horizon. `Project` groups a change with deliverables, stage model, dependencies, carrying/closure costs and acceptance scope. `Workstream` groups recurring related work with its service mandate, cadence and continuity owner. Their exact parent links are optional rather than a mandatory four-level hierarchy. A small correction can reference one goal and one Case directly. Each record retains principal/venture boundaries; none grants resources or establishes legal identity. Parent membership changes do not move duties or reinterpret historical outcomes.

**SPECIFICATION.** Decomposition starts from the outcome and surviving obligations. The responsible planner identifies the next uncertainty, produces a finite dependency graph and separate acceptance criteria, assigns actual custody and checks resource/deadline feasibility. Planning effort itself consumes a bounded WorkOrder. Its output must enable work or answer a decision; another plan with renamed subtasks is not progress. Stable known procedures can be admitted directly. Unfamiliar work starts with a bounded discriminator before a large commitment, with useful independent work continuing.

**SPECIFICATION.** `WorkDependency` has source/target exact refs, kind `requires_output/requires_authority/requires_capacity/shared_resource/knowledge_question`, a typed predicate, evidence freshness, custodian and latest responsible resolution time. Capability catalog dependencies mean available interfaces and conditional step guards, not required previously completed capability runs. C02 validates the actual execution graph at admission: cycles in required outputs produce a named blocker and a proposed cut, such as a provisional hypothesis followed by a later validation. It cannot synthesize missing customer or financial evidence to break the cycle. Readiness dependencies are met by actual procedure/performer availability where required, not prior completed sales.

**SPECIFICATION.** `Blocker` states exactly what cannot proceed, what observation/decision/capacity would unblock it, who can provide that result, next check and due impact. Unknown cause differs from known impossibility. Its state is `open/investigating/awaiting_dependency/resolved/accepted_limit`; only supported evidence satisfies the predicate. An accepted limit parks or narrows affected work and preserves duty ownership. Silence, a new timer, or a new worker name cannot resolve it. The outcome sponsor notices combined drift and incompatible local successes through milestone review, not by relying on workers to volunteer failure.

**DESIGN PROPOSAL.** WIP defaults to one running WorkOrder per temporary executor and one native producer per newly admitted execution profile until a bounded capacity trial establishes a higher limit. **UNKNOWN:** This is an initial engineering default, not a founder attention preference or performance fact. Global admission takes the minimum of actual executor slots, resource reservations, independent review capacity and human/service availability. Protected due work keeps its reserved lane. More backlog does not create more capable people or provider allowance.

**SPECIFICATION — admission computes the class before the kind.** C02 derives the reached class set of a newly arriving job **before** it decides what kind of work it is, and records it on the `AdmissionRecord` ( `(origin, arrival_seq)`; `opened → {admitted, refused, parked, escalated}` ). An unknown job is therefore **bounded before it is understood**, so mistyping it into the nearest existing kind cannot lower its class (R5-15, TC-40). **Removal criterion (falsifier form):** if over a fixed window every admitted job's pre-kind class set equals its post-kind class set, the pre-kind derivation adds nothing and the ordering is dropped.

**SPECIFICATION — refusal is a terminal state of the same record.** `AdmissionRecord → refused` requires a **named failed predicate** and its own acceptance owner; the refusal is not a silence, not a park and not a deleted arrival. **Silence is not refusal.** A refusal that is communicated outward is itself an outward effect and carries its own reached class set. Nothing in the surveyed frameworks refuses a job with a reason (R3 §9 F-1), so this is built rather than imported.

**SPECIFICATION — typing has three admissible outcomes and no confidence threshold.** Typing an arriving job returns **matched**, **`no_match`** or **`budget_exhausted`** — the same three that §10 already registers for `SkillSelection`, and for the same reason: `no_match` is a searched answer and `budget_exhausted` is an unfinished search. A fourth outcome, *typed into the nearest existing kind*, is a **recorded failure and is never scored as a success**. Anything that is not a deterministic predicate match is `no_match`; there is no confidence score and no threshold. **The cost is named rather than hidden** (F-7's narrowing): genuine work in unfamiliar wording will land in `no_match` more often than a scored matcher would put it there, which is why fixture 17 of §9's adverse table is a **false-exclusion control that must pass**. Where the class of an arriving job is unresolvable on one or more dimensions, it resolves to the **ceiling of the unresolved dimensions**, never to their floor and never to a default.

**SPECIFICATION — the disposition of work nothing can handle is per class, not uniform.** At the two lowest reached classes the work **parks** with an owner and a review date. At the middle two it **escalates on a timer** to the standing holder for that duty class (§12), and **where that duty class has no admitted standing holder the escalation goes to the ordered custody resolver of [`03-company-capabilities.md`](03-company-capabilities.md), whose last tier is the designated maintenance/discovery custodian** — the band's default recipient, stated in the paragraph below. At the two highest it is **refused**, and a decision packet is routed to the human authority named in [`04-human-operation.md`](04-human-operation.md)'s `AuthorityMatrix`. Work of an unknown kind receives a named `unclassified-effect` grant class: per-authorisation, expiring, with a value ceiling and a human authoriser per effect, plus a per-class ceiling on what one unclassified-path custodian may authorise without a second party. **The omnibus standing grant is refused.** **UNKNOWN — founder-owned parameters, no default invented (selection record §6.2, MD-10):** the consequence ceiling and the value ceiling. **Until both are set this class admits no effect steps at all**, and unknown work terminates in a decision packet rather than in a permissive branch.

**SPECIFICATION — admissions narrow by computation, not by judgement (R-D09).** When a standing acceptance role is unfilled or suspended, **admission of new work in that duty class stops**, computed by the same predicate that resolves the acceptance owner, by C02, inside the same protected transaction that would otherwise have admitted the work. No party announces a narrowing and none may decline to perform it. **UNKNOWN — founder-owned parameter (selection record §6.2, MD-09):** the narrowing *shape*. The stated default is **class-stop** — admission in the affected duty class halts entirely; the alternative is a graded share. The founder owns it because narrowing policy is what the company stops taking on.

**DESIGN PROPOSAL — the middle band's terminus when no holder exists, and its deadline behaviour (F6A-01).** The two lowest classes park with an owner and the two highest refuse with a packet to a named human authority; only the middle band routed to a §12 holder, and §12 refuses to admit a holder for a duty class no frozen fixture exercises — so the ladder could name a recipient that does not exist. **Supplier insolvency during a paid pre-order is the case: it reaches the external-contact and economic classes, no admitted holder covers it, and the escalation had nowhere to land.** It lands here. **Where the duty class has no admitted standing holder, the escalation is routed to [`03-company-capabilities.md`](03-company-capabilities.md)'s ordered custody resolver** — promise sponsor, otherwise the service mandate, otherwise the designated maintenance/discovery custodian — and the resulting `ResponsibilityAssignment` records `custody_basis = maintenance_custodian` when it reaches that last tier. The terminus exists unconditionally because that tier has no further branch. **Custody is ownership, not authority.** `03`'s resolver *"assigns ownership, not new grants"*, so a custodian holding work that needs authority it does not have routes a decision packet to [`04-human-operation.md`](04-human-operation.md)'s `AuthorityMatrix`, exactly as the two highest classes do, and never acts above its class. **The deadline behaviour is `03`'s existing one and no new timer is created**: the escalation carries a latest responsible time; expiry activates the accepted alternate through the existing `alternate_assignment_ref`, `deadlines` and `expires_at` fields; a contested assignment is still custody and does not suspend it; and if custody is still unaccepted after the alternate's expiry, **admission in that duty class stops** by the computed predicate of R-D09 above and the unaccepted escalation is refused with a named failed predicate rather than left assigned and silent. That is the explicit awaiting-principal state with a deadline and a standing owner that §6's fourth silent-drop counter promises.

**DESIGN PROPOSAL — acceptance at the economic/contractual class is unsampleable in one half and sampled in the other, and the founder's load is bounded by narrowing rather than by the length of his day (F6B-05).** The consolidation asked for either *"a sampling rule at C3 equivalent to the one §6.3 applies at C2, or an explicit statement that C3 acceptance is unsampleable and the resulting per-week count"* (AC-M4-01). Neither existed anywhere in this package, and the answer requires separating two acts this chapter had been calling one.

**The release authorisation is NOT sampled, per effect.** An outward release at the economic/contractual class requires a human approver for that effect (§7, R-G11). Sampling a release means releasing the unsampled ones with no approver, which is not a lighter version of the rule but its absence. **This half is unsampleable by construction, and that is the explicit statement the second limb asked for.**

**The outcome acceptance IS sampled, and the sampling rule is the one [`04-human-operation.md`](04-human-operation.md) already carries rather than a new one.** Whether an accepted outcome was the right one is reviewed afterwards on the founder's participation cycle: **the adverse stratum is exhaustive** — every dispute, refund, grievance, breached stated minimum and first-of-kind counterparty — and **the ordinary stratum is drawn to fill the declared batch minutes, adverse first**, by `04`'s existing seeded within-strata selection, outside the account producer's write authority, with the denominator and the empty strata recorded. This mirrors [`06-knowledge-evidence-evaluation.md`](06-knowledge-evidence-evaluation.md) §6's existing rule for the reversible classes — *"deterministic validation and sampled outcome review under an admitted acceptance policy"* — at the class above it. **No fraction is invented here**: the sample size is whatever the founder's declared batch minutes hold, so the parameter is one he already sets in his `ParticipationPlan` rather than one this chapter guesses.

**SPECIFICATION — the named failure condition, and it is [DIRECTIVE §8.18](../../inputs/DIRECTIVE.md)'s: the founder becomes a full-time reviewer.** It is declared to have occurred when **the unsampleable half alone — the per-effect approvals at the economic/contractual class plus the exhaustive adverse stratum — exceeds the declared batch minutes for two consecutive participation cycles.** The response is **admission narrowing in that duty class**, computed by the same predicate as R-D09 above, inside the same protected transaction, with no party announcing it and none able to decline it. It is never a longer founder day and never an unreviewed release. The overload is therefore a visible state with an owner rather than a private cost, which is the whole of what W12's failure condition asks.

**UNKNOWN — the resulting per-week count, which is owed rather than estimated.** How many acts per operating week reach the economic/contractual class and so require the founder's approval is a function of admitted volume nobody has measured; W12's own probe is *"run a month of the candidate's normal operation, count what reaches the founder and why"*, and **the count is not derivable from this specification**. It is registered as an owed measurement with its instrument in §13 below, and until it runs the protection against the load is the narrowing rule above rather than an estimate of the number.

## 3. Workflow, run and step execution

**SPECIFICATION — amended in WORK-1.1; no record is renamed and no record is added here.** `WorkflowDefinition` is an immutable versioned procedure: typed input/output ports, named steps, deterministic guards, allowed adaptive branches, stage rules, maximum elapsed/idle time, retry/compensation contracts, evidence and acceptance roles. **`WorkflowDefinition` and `StepExecution` additionally carry six declared fields** (R-L2, [selection record](../F2/05-selection-record.md) §12.3's changed-records list): `step_kind ∈ {compute, model, human, professional, effect}`; `declared_read_set`; `declared_grants`; `validator_ref`; `branch_set`; and `critical_fields`. These are **fields on the existing registry records** — the candidate-era proposal to rename these records to `Procedure`/`Step`/`Journal` is refused (R-X02, closing AT-M3-02), and the alias table of [`11-schemas-state-contracts.md`](11-schemas-state-contracts.md) maps every candidate name to its registry name so that no candidate-era name is ever admitted as a record name. A fixed path handles known repeatable work; an adaptive step produces a proposed next plan under the same scope and allowance. The admission owner chooses the mode using uncertainty and cost evidence, not whether the producer prefers more freedom. Unknown cases leave the fixed path through an owned exception; they do not silently bypass gates.

**SPECIFICATION.** `WorkflowRun` pins definition, Case, causal episode, exact inputs and current step cursor. `StepExecution` pins step definition and WorkOrder; its execution projection follows the canonical order/report/acceptance records. A run follows `prepared/running/waiting/parked/acceptance_pending/accepted/failed/cancelled`. A step follows `ready/dispatched/running/reported/accepted/rejected/waiting/cancelled`. Only C02 advances the cursor, in the same protected transaction that records the step result and creates the next work intent. C06 judgment plus the required sponsor acceptance permits a run's accepted state. Actual effect states remain OperationStatus dimensions.

**SPECIFICATION — amended in WORK-1.1.** Each step declares an input contract, performer class, read/write resource scope, result envelope, allowed outcomes, exit predicate and next branch. **The loader delivers the step's `declared_read_set` and records what it actually delivered; the caller's claimed read list is not trusted** — the same rule [`06-knowledge-evidence-evaluation.md`](06-knowledge-evidence-evaluation.md) §2 already states for context assembly, now made a property of every step. This is what converts *"the checker did not read the producer's rationale"* from an assertion into a manifest fact, and a design in which a worker assembles its own context cannot make that claim at all. **A guard is a pure function over typed outputs and journal state; a model's output is an input to a guard and never a jump** — control flow is trusted, model output is data, and the published utility price of that separation is paid deliberately (R2 F-09). **One effect per effect step, and the step is the idempotency unit**: on resume after an interrupt the whole step restarts, so a human approval step that shared its node with the payment it approved could duplicate that payment (R3 F29, F30). **The step boundary is the checkpoint** (R-D19): every step boundary is a close-out point and the cost is carried, so no separate reserved-closing-allowance predicate exists — the alternative needed a denominator the round establishes does not exist (AT-M1-03). Deterministic transformations execute without a model. Nondeterministic model/tool/human results are captured once as attributable data; replay consumes the recorded result only while current validity permits it. A live regeneration is a new attempt, never “replay.” External operations are proposed and released through C04, outside database transactions. Domain acceptance can require an actual professional result or customer condition; a successful dispatch does not satisfy that guard.

**SPECIFICATION.** Stage is an epistemic/business position such as proposed, investigated, validated, deliverable or maintaining. Status is whether execution is running, blocked or finished. Workflow definitions choose relevant stages; they do not impose a coding pipeline on finance or support. A small deterministic correction can use one production step and one required acceptance check. A declared guard may establish that a stage is inapplicable, with a reason; current authority, data permission, required review and actual duty-discharge predicates cannot be skipped. New contrary evidence can move the current projection backward through a recorded invalidation/review decision, preserving earlier acceptance history.

**SPECIFICATION.** Changing a definition creates a new revision. Existing runs remain pinned if compatible and safe. A migration plan names in-flight states, old/new step mapping, preserved outputs/unknown effects, invalidated acceptance, current grants and rollback. C02 parks incompatible runs, and C04/C08 fence affected authority where required. Resuming from the middle requires exact accepted checkpoint, available inputs, compatible code/definition and current restrictions. The system does not replay a payment or customer contact to reconstruct a cursor.

**SPECIFICATION.** Compensation is its own typed work with authority and acceptance. It may repair a consequence while leaving history and obligations. Steps declare `no_compensation`, an actual compensating procedure, or a need for a competent decision. A failed refund, apology or supplier replacement remains an owned duty; cancelling the workflow never makes those results true. Integration tests must inspect the combined journey after individually correct steps.

**SPECIFICATION — the zero-allowance step kind, and maximising its share.** `step_kind: compute` consumes no model allowance. Determinism is the only lever that cuts subscription consumption without cutting work, so raising the `compute` share of a procedure is a first-class design goal of every procedure admission, and the share is reported per procedure version.

**SPECIFICATION — procedure admission refuses a model-selected acceptance strength (R-X19, closing AS-M3-01).** A `branch_set` in which a **model-authored typed value selects between acceptance strengths** for one artifact is refused at admission, naming the failed predicate. Acceptance-strength selection is a guard over journal state and consequence class, never a producer's choice: typing the checker's *inputs* does not help if the producer still picks the *checker*. A model step may supply a typed value into a declared field of declared type and domain, and that is the whole of what it may do to control flow.

**SPECIFICATION — a producing run may not select its own checker.** The checker's procedure comes from committed configuration, not from the producing run. A routing component that can choose who checks its own work has not achieved procedural independence.

**SPECIFICATION — the adaptive envelope has a named author (R-X04, closing AT-M3-04).** An adaptive step's envelope is authored by the **capability owner at procedure admission**, never by the resuming or adapting attempt. The envelope of `unclassified-work/v1` is written out rather than left implied: step kinds `{compute, model, human}`; read set = the work record plus its cited sources; **effect classes = none**; one launch per step; and a declared maximum step count. A procedure whose adaptive envelope is unstated is not admissible.

**SPECIFICATION — one parameter, not two (R-X05, closing AT-M3-05).** The collapse threshold (when an adaptive procedure collapses to a fixed path) and the retirement window (when that procedure version retires) are **one parameter with one owner** — the capability owner — declared per procedure at admission. Two numbers for one concept is what produced the finding; they cannot be set independently.

**SPECIFICATION — `unclassified-work/v1` has a clock somebody owns.** Work admitted under it carries a **declared maximum age**, and a breach of that age is **itself admitted work** with an owner, not a log line. Unknown work is therefore neither dropped nor parked forever.

**SPECIFICATION — a drafted procedure is not an executable one.** A procedure drafted by a model becomes executable only after a passing test suite **and** a human capability owner's acceptance. A control-flow structure authored by a model from untrusted input is precisely the thing the trust boundary exists to prevent (R3 F11). **A declared grant is resolved against the grant policy at admission**, so a declaration no configuration backs is refused rather than carried — the decorative-declaration loophole, observed in this repository as 44 capability declarations that nothing backed (R3 F57, F60). **The grant policy is not a new object, and naming it is the point (F6D-06): `declared_grants` is `Ref<Grant>[]` and is `required` on both `WorkflowDefinition` and `StepExecution`, and the registry of `Grant` records — issued by C04, each carrying issuer mandate, holder, purpose, destinations, bounds and expiry — is the policy it resolves against.** A second grant-policy record would be a second authority over one question, and two implementations of one rule disagree at the moment it matters. **Resolution is a conjunct on the admission edge** — `guard.grant.declared_resolves_to_live_grant` — and **the step is refused, naming the failed predicate, when a declared grant does not resolve to a live `Grant` held by the step's executing identity and no wider than what the step declares**; the paired benign case is a step whose declared grants all resolve, which must not be refused. **It is a typed ref and not bounded text**, because free text is the decorative form of this same declaration: a string cannot be resolved against anything, and `validator_ref` on the same record was already a typed ref, so the typed form was available and unused. **Arrival is a different fact from scope**: `GrantDeliveryReceipt` and `grant_arrival_attested` (§4) attest that a grant arrived, never that it was the right one, and this rule is the half that checks scope.

**SPECIFICATION — permissions do not compose; they decompose.** Three permissions needed by one task become **three effect steps**, and the union grant never exists anywhere. This answers [the F2 acceptance protocol](../F2/00-acceptance-protocol.md) §5 item 6 — whether a composite grant is minted, borrowed or refused — with **refused, not minted**.

**SPECIFICATION — removal criteria for the L2 additions, in falsifier form (R-X26).** The declared read set and the step model are removed when **a newer model passes every step's declared validator with the step merged into its neighbour or removed**. The precedent runs against its own authors' interest and is why the criterion is stated rather than assumed: a scaffold's contribution is a function of the model generation that motivated it and must be re-ablated when the model changes. The `critical_fields` marking is removed when, over a window, no resumed attempt's behaviour differs with the marking present or absent.

**SPECIFICATION — what marks a field critical, and who marks it (R-D18).** A field is critical if a `ParameterAuthority` governs it, if it is a `ConstraintSet` member, or if the procedure declares it in `critical_fields`. ## 5. Delegation, messages and accountable handoffs

**SPECIFICATION.** C02 owns assignment. An executor may propose a child only with a concrete independent result, exact inputs, acceptance role, scope exclusions, deadline, allowance and expected coordination benefit. Splitting is useful when independent bounded work can reduce elapsed time or provide a required different observation more than it adds transfer, review and integration cost. Unknown benefit gets a finite comparison, not permanent fan-out. The default maximum depth is one child layer; a second requires explicit admission rationale and reserved coordination capacity. Deeper trees require a reviewed template change. Depth is never a substitute for the root causal ceiling.

**SPECIFICATION.** `Delegation` links parent/child WorkOrders, original outcome sponsor, proposed performer, reserved share, receipt/response/latest-result times, nondelegable decisions and Continuation. The child cannot further delegate founder values, professional standing, independent acceptance, access that it cannot lawfully transfer, or the parent's responsibility. Parent sponsorship remains until an actual accepted responsibility transfer. A parent cannot label a difficult decision “delegated” to avoid exercising its own mandate.

**SPECIFICATION.** `WorkMessage` has kind `assignment/question/observation/objection/correction/progress/result/stop_notice`, sender/recipient identities, exact subject refs, permitted payload/artifacts, request correlation, delivery expiry, response deadline and required action. Durable transport receipt means the recipient inbox stored the message. `MessageAcknowledgment` distinguishes received, understood-scope, accepted-assignment, refused and answered. Assignment acceptance requires current authority/capacity and a check of purpose, exclusions and expected result. A receipt, model paraphrase or emoji cannot transfer duties.

**SPECIFICATION.** Duplicate message identity/content returns its recorded result; changed content under that identity conflicts. Delivery retries reuse the same identity and consume the original causal allowance. Expiry prevents a stale assignment from starting. A worker that stops acknowledging or heartbeating loses its execution lease under the kernel protocol; the owner records unknown activity and reconciles before reassignment. No process-liveness observation grants exclusive external authority. Replies received after transfer remain attributable evidence for the current custodian, not commands from a resurrected owner.

**SPECIFICATION.** Questions identify the exact missing fact/decision, why it matters, needed-by time, default behavior and independent work that can continue. Objections preserve challenged scope, contrary evidence and requested investigation; they do not automatically impose suspension or rewrite direction. Urgency derives from actual latest responsible time and a standing interruption rule. Nonurgent requests batch into the human participation window. No answer invokes the recorded bounded fallback, substitute or parked state; it never means approval. A founder correction produces an exact amended intent/decision or factual correction and a dependent-work invalidation/understanding check.

**SPECIFICATION.** Result transfer carries typed outputs and partial-state flags, exact intent/criteria, warnings, amounts/units, unknowns, contradictions, source/omission refs, remaining duties, pending effects, resources used and next action. A summary is an additional derivative beside the canonical Continuation, never its replacement. The receiver checks critical predicates against originals before acting. Schema mismatch yields a quarantined report and bounded repair request; free-form explanation can accompany typed fields but cannot fill missing required evidence with plausible prose. Each transformation records losses; the next step can demand the original or stop the affected inference.

**SPECIFICATION — `ConstraintSet` on every boundary crossing, new in WORK-1.1 (R-X27).** Identity is a **content digest**; the record is **immutable**; the producing structure writes it and it is validated at the boundary. A constraint set is required on **every transfer the fixtures name — including the continuation and the founder-facing brief**, not only on machine-to-machine handoffs. **A receiver may act only on the members it can restate as typed values.** Prose accompanying a constraint set is evidence and is never a substitute for a member. **A transfer whose constraint set fails schema validation produces a quarantined report and a bounded repair request, never a best-effort continue** — which is the rule §5 already states for result transfer, now applied to the constraints themselves. The reason is measured and one-directional: ordinary facts survive a compressed transfer at about 0.97 while rules, exclusions, deadlines and promises survive at about 0.57, and typed constraints leaked **0 of 48** where prose leaked 73% (R2 F-04, F-05; X13; AG-09). The answer to "handoffs lose things" is therefore **type what crosses**, not split less. **Removal criterion:** if over a window no transfer's typed members differ from what the accompanying prose already carried without loss, the typing is dropped.

**SPECIFICATION — consultation and handoff are keyed to class.** **Consultation is the default at the external-disclosure class and above**; handoff is permitted below it and requires an `AcceptanceInterval` (below). The distinction is that consultation leaves the parent accountable while a handoff moves accountability, and moving accountability across a class boundary is what the higher classes forbid without a record.

**SPECIFICATION — `AcceptanceInterval`, new in WORK-1.1 (R-D17).** Identity `(work_order_ref, submission_seq)`; states `declared_done → in_acceptance → accepted | rejected`; the **interval holder is the producing structure's sponsor** and the **acceptance owner writes the terminal edge**. It inherits the transfer's reached class set and that set's deadline. **`* → accepted` is rejected by the writer guard when the resolution reason is empty.** At the economic class and above, an **undecided interval escalates to the standing holder at the latest responsible time and the effect does not release**. This record is deliberately **not** the registry's `HandoffAcceptance`, which governs unchanged, is owned by S1-C07, has a different state set and a human-only command; naming the work-layer object separately is what keeps this amendment out of irreversible tier. **Removal criterion:** if over a window every interval's terminal edge is written in the same transaction that declared completion, the interval is not a state anyone occupies and it is dropped.

**SPECIFICATION — the model-to-model return (R-D13, closing AS-M1-01).** A model-to-model return exists **only on a declared procedure edge**, it **crosses the loader**, it delivers **typed outputs and typed `ConstraintSet` members only**, and any prose is **stored at a `Ref` and not delivered**. An unfiltered consultation return is a channel straight into the identity holding the effect grants, and the rule that would filter it cannot be model-enforced. The two candidates in the round with no model-to-model channel at all carried **zero** propagation findings, which is the one divide in that round carrying independent information.

**SPECIFICATION — a width ceiling as well as a depth ceiling (R-X16).** The existing default maximum depth of one child layer is unchanged. **A width ceiling applies per attempt and is expressed over distinct read sets, not over cost**, with the same owner (C01) and the same checkpoint as the depth ceiling. Fifty sequential consultations, each individually cheap, sit inside one budget and are a fan-out incident that a cost ceiling cannot see; two consultations over one read set are not, and must not trip it.

## 6. Concurrency, failure, retry and stop

**SPECIFICATION.** `WorkspaceAssignment` pins repository/source root, base revision, permitted paths/resources, task identity and write lease. Separate standalone checkouts are the protected-source default where shared Git/configuration could violate the admitted boundary; worktrees are an allowed concurrency convenience only within a verified compatible trust scope. Worktrees alone do not isolate processes, ports, databases or network effects, as discussed in L04 (**SOURCE CLAIM**). One writer holds an exact mutable artifact/resource scope; nonoverlapping writers can proceed. A merge WorkOrder checks textual and semantic compatibility against the current base, tests the combined result and obtains independent acceptance. A clean textual merge is not behavioral compatibility.

**SPECIFICATION.** Two branches can propose changes to the same product meaning without touching the same file. `WorkDependency` shared-resource and semantic-conflict refs therefore supplement path leases. C02 detects new overlap and pauses only the dependent integration; C04 applies the kernel's union-scope migration where obligations/issuers/conflicts changed. The resolver cannot silently discard either proposal. Original work and its costs remain visible.

**SPECIFICATION.** `FailureRecord` captures error class, exact procedure/input/dependency versions, observed cause, unknowns, affected scope, attempts and proposed next discriminator. Its fingerprint uses stable semantic cause/scope plus normalized error category; cosmetic wording or a new agent ID cannot create fresh allowance. Error classes are transient internal failure, invalid input, auth/permission failure, provider capacity, stale context, invariant breach, unknown effect, competence gap and no progress. Internal transaction retries remain the kernel's bounded pure-transaction rule. External retries remain the authority/adapter contract; this document creates no generic resend loop.

**DESIGN PROPOSAL.** For semantic production, the initial rule allows one retry after a changed input, environment or method is identified within the existing allowance. Two failed attempts with the same cause and no accepted progress open a Blocker; they do not prove impossibility. A template may justify another finite policy using actual conformance evidence. Capacity/auth failures park until a verified changed condition; repeated model calls to rediscover exhaustion are forbidden. C02 checks heartbeat separately from meaningful progress: accepted output, resolved predicate or a tested hypothesis with an honest negative result. Rework time, rejected attempts and abandoned outputs stay in the denominator.

**SPECIFICATION.** Stop preserves five facts from human operation: request, release fence, worker cessation, external-effect reconciliation and completed remedy. C02 cancels not-yet-dispatched internal work, requests admitted worker stop and prepares continuation under its reserved closing allowance. Expired leases fence writes; they do not prove no external effect. Recovery reconciles actual OperationStatus before repeating any business action. Unrelated authorized service continues under its separate resources. Abandonment always identifies current custodian, allowed cleanup, remaining deadlines and reopening condition.

**SPECIFICATION — an attempt ceiling per work order (R-X10).** A work order carries a **maximum attempt count with a named owner, C02, and a stated behaviour at the ceiling: park, with an owner and a deadline.** Bounded retry is by error class, and **two failures with the same cause open a `Blocker`** — the rule §6 already states, now bounded at the work-order level as well as the attempt level, so that repetition cannot be laundered through fresh attempts. `FailureRecord` names **`no_progress` as a terminal error class with a named recipient**; a terminal class with no recipient is a silent drop. A **progress predicate applies to every reserved lane**: a named recipient is told when a lane's consumption carries **no accepted outcome across a reset window**, which is the only way a reserved lane's waste becomes visible to anyone.

**SPECIFICATION — `EffectIdentity`, new in WORK-1.1.** Identity `(effect_class, counterparty, payload_digest)`; lifecycle `allocated → claimed → observed`; allocated by **C04 before release**. **A second claimant joins the first and inherits its outcome — it does not race and does not re-release.** **That sentence is a schema requirement and not a narration (F6D-11): the business triple `(effect_class, counterparty, payload_digest)` carries a uniqueness constraint, so two allocations of one triple are one allocation; `first_claimant_ref` is `required` rather than optional; and a conjunct on `allocated → claimed` asserts that a claim whose triple already carries a `first_claimant_ref` inherits that outcome rather than re-releasing.** Without the uniqueness the record's registry identity is `(company_id, record_id, revision)` and the triple is three ordinary payload fields, which leaves an implementer to choose between a unique-index conflict, a read-then-join and two rows — three different systems, and the protocol's tenth (d)-class example is exactly that choice. **The adverse case is a second claimant that re-releases, which must fail; the benign case is a first claimant releasing once, which must not be flagged.** De-correlation is deliberate and designed alongside the shared record, not after it: **reserved name ranges** are allocated centrally and a **rate-anomaly monitor** watches for correlated choices. The cause being defended against is **correlated behaviour between identical models**, not divergent context — eighteen of thirty workers chose the identical branch name, and a job queue took 2.4 million requests to accept 117 (R1 F-17, AG-17). **A shared authoritative view does not fix this and may amplify it.** **Removal criterion:** if over a window no second claimant ever arrives for an allocated identity, the allocator is dropped and the idempotency record on the effect stands alone.

**SPECIFICATION — the four silent-drop shapes, named with their counters.** A drop that nobody is told about is the failure mode this section exists to prevent, and it has four observed shapes. **(1) Overflow passed through untouched** — counter: overflow routes to a **named destination with an alarm and a named reader**, never to `/dev/null` and never back to the producer. **(2) A queue nobody polls** — counter: every queue declares its reader and its maximum age, and a breach of that age is admitted work. **(3) A holding destination whose retention is shorter than the interruption** — counter: retention on any holding destination **exceeds the longest plausible outage**, and the outage figure is stated, not assumed. **(4) An escalation ladder ending assigned-and-silent** — counter: **the terminus of every ladder is the registered `AdmissionRecord.escalated` phase**, whose criterion demands a **named acceptance holder standing at `staffed`**, a recorded **`escalation_deadline`** and the **duty class** escalated in (§12), because an escalation whose last rung is a name is an escalation to nobody. *Amended 2026-09-14 (F6C-12): this counter read "an explicit **awaiting-principal state** with a deadline and a standing owner". That string named no registered state — it occurred once in the specification chapters, in this very sentence, and zero times in the contract registry, while §12 defines no such state — and the substance was already registered under another name. **This is naming, not mechanism**: nothing about the ladder's terminus changes. §10 exists for the converse case and states the governing principle, *"A state that exists in the machine and nowhere in the prose is a state two implementers define differently"*; a state that exists in the prose and nowhere in the machine costs the same.*

## 7. Durable schedules and capacity gaps

**SPECIFICATION.** `Schedule` binds an accepted workflow/capability version, actual timezone/calendar rule, activation interval, occurrence window, latest responsible start, catch-up/concurrency policy, authority, resource class, sponsor and alternate. The initial scheduler is the kernel's durable SQL timer sweep plus event-triggered wakeups; no model runs merely to notice time. `ScheduleOccurrence` identity is schedule revision plus intended local/calendar occurrence and resolved UTC instant. The timezone-rule version and ambiguous/nonexistent local-time policy are explicit. A clock jump cannot create a second logical occurrence.

**SPECIFICATION.** Every schedule chooses one missed-occurrence policy. **Individual reconciliation** preserves each due invoice, service occurrence or reporting duty and its actual deadline. **Coalesce** produces one current research/maintenance assessment with the omitted windows listed; it cannot merge distinct rights. **Skip-expired** discards obsolete promotional opportunities with a reason and no catch-up blast. **Escalate** activates the accepted custodian/alternate when a missed action needs actual competent judgment. Defaults offered by procedure kind must be explicitly adopted; the software does not invent statutory deadlines or customer agreement terms.

**SPECIFICATION.** Occurrence states are `planned/due/admitted/running/completed/missed/disposed`; completion follows actual workflow acceptance. Missing work is not automatically marked completed when the next occurrence starts. The scheduling owner records what was intended, actual wake/start, lateness, duplicates suppressed, partial work and remaining duty. Concurrency defaults forbid overlapping instances of the same effect-bearing occurrence; independent read-only assessment can overlap only under separate input/resource admission.

**SPECIFICATION.** Unattended work needs all prerequisites in standing mandates, available context/tools, finite budgets, acceptance and no-answer/continuity behavior before starting. Attended mode does not weaken authority or allow unavailable service. When the company has no due or authorized useful work, executors idle; planned discovery runs only within its adopted mandate. During a gap, surviving local work can checkpoint through D1, due service uses actually available independent routes, and unavailable performance remains an operational failure. Return presents the human account's actual changes, missing periods and unresolved consequences.

**SPECIFICATION — `StandingInterest` and the armed set, new in WORK-1.1 (R-L3).** `StandingInterest` has identity `(id, version)` and lifecycle `proposed → trial → admitted → suspended → retired`; the **maintenance custodian proposes and the capability owner admits**. `ArmedSet` has identity `(journal_position)`, is a **computed projection with no lifecycle, and nobody writes it**. **Relevance is computed, and the armed set is unstoppable**: it is evaluated by deterministic code over typed fields after **every committed transition**, and **no component may prevent membership** — in particular, the admission authority holds no write access to any precondition-bearing kind. This is what makes a deferral a **visible state with a latest responsible time** rather than an absence indistinguishable from an oversight, which is the defect S1.0 carries because nothing exists until the case authority admits it (R5-01, R5-02).

**SPECIFICATION — the hard rules of layer 3.** **No precondition may invoke a model.** A model-evaluated gate is a model-placed boundary, which cannot hold, and determinism is the only free lever on capacity (AG-08; R4 F4, F6; R8 B-7). **An interest arms only when every declared prerequisite holds simultaneously, unexpired, uncontradicted, and at or above its required trust class** — the all-prerequisites shape, not a single-prerequisite trigger (R3 F33, D-15). **Trust class gates what an entry may activate and is never a weight on a ranking**: provenance-weighted ranking was indistinguishable from no defence at its shipped weight and took evidence recall to exactly zero at the weight that worked (R1 F-10). **The armed set is recomputed, never carried in a summary**, so a pre-reset summary that omits a decision cannot cause the wrong activation — the summary is not what activates. **A standing interest may write only a `proposed` revision of a constraint** (R-D23); `proposed → endorsed` remains C01's. **A proposal declaring a writer key is refused, naming the failed predicate** (R-D16): writer keys are assigned only by the record authority, and a trial may write only into kinds whose writer is already "any activation". **`proposed → trial` is admissible only at the two lowest effect classes**; read-only and internal-artifact capabilities proceed on an **expiring bounded trial** under a standing mandate while approval is pending, and outward-draft and outward-release require a human approver (R-G11). **UNKNOWN — founder packet MD-03 (selection record §6.5):** who that human approver is, its ceiling, and what happens during a founder absence. No default is invented; until it is answered, outward classes have no approver and therefore do not proceed.

**SPECIFICATION — admission is bounded to five verbs and five prohibitions.** The verbs are **admit, defer, shed, refuse, rank**. Among the prohibitions, the one that binds hardest is that **the admitter may not accept work it admitted**; the ordered custody resolver of [`03-company-capabilities.md`](03-company-capabilities.md) therefore **skips the admitting identity and continues to the next tier, recording `custody_tie_break_reason = admitter_excluded`** (R-X06). The admission authority gains one refusal predicate it lacked: **a per-origin arming rate** (R-X21). A single origin that can arm interests without bound is a disturbance loop, and the evaluation protocol for that predicate is stated here rather than cited elsewhere — baseline the per-origin arming rate over a declared window, unit is armings per origin per window, repetition is every window, the stopping rule is two consecutive windows above the declared rate, and the owner is C02.

**SPECIFICATION — the unmatched pool, and its residue named.** `UnmatchedPoolEntry` has identity `(work_record_ref)` and lifecycle `landed → claimed | refused | escalated`, written by the pool interest **deterministically**. It is the **computable complement** of the armed set: whatever armed no interest lands in it. **Retention exceeds the longest plausible outage** and **an alarm on arrival has a named reader**. **And the residue is stated rather than implied: the pool cannot catch an entry that armed the *wrong* interest.** A catch-all that does not name what it cannot catch is decoration (R5-09). **Removal criterion for layer 3, in falsifier form:** over one month, if **every item whose relevance nobody currently holds in mind is surfaced within its latest responsible time by the world-change sweep specified in the next paragraph**, arming buys nothing and is removed. *Amended 2026-09-14 (F6A-02): the comparator read “**the existing scheduled review**”, which named nothing — no scheduled review is specified in this chapter or in [`02-authority-recovery.md`](02-authority-recovery.md), where the string “scheduled review” occurs zero times (checked 2026-09-14).* **Or** if the deterministic-predicate fraction falls below the threshold set under R-X25, layer 3 is **withdrawn rather than relaxed** — relaxing it for even one precondition class would reintroduce the model-placed boundary the layer exists to avoid. **UNKNOWN — founder parameter, no default (R-X25):** the value of that threshold. The measurement itself — the fraction of the company's conditions expressible as deterministic typed predicates — is owed with a baseline, a unit, a stopping rule and an owner, and it is cheap and unrun.

**SPECIFICATION — the world-change sweep, new 2026-09-14 (F6A-02).** The armed set is computed over committed transitions and `UnmatchedPoolEntry` is its complement over work records, so **an external state change that writes no transition and produces no work record neither arms nor lands in the pool** — a jurisdictional policy change is the worked case, and it is a second residue beside the one this section already names. **The entry path for such work is a named periodic sweep in this chapter, not a review assumed to exist elsewhere.** A `Schedule` whose accepted capability version is the **world-change sweep** runs under this section's ordinary rules: **owner C02**, which holds the schedule and its alternate; **missed-occurrence policy `individual reconciliation`** — never `coalesce` and never `skip-expired`, because an external change that looks obsolete is exactly what this sweep exists not to discard; and a **latest responsible start of one occurrence per review period**, the period §12 prices holder review over. ## 8. Instructions and reusable skills

**SPECIFICATION.** `InstructionBundle` contains a short stable purpose/constraints contract, authority hierarchy references, typed operating procedure, response requirements, examples and change history. Task-specific facts, scope and current rights arrive through the WorkOrder/ContextManifest. No secret, reusable credential, private cross-purpose profile or supposed hidden authority belongs in an instruction. A prompt can guide interpretation; deterministic boundaries enforce permissions, schema, resource use, isolation and release. Repeated instruction noncompliance on a critical rule is evidence to change the mechanism or eligibility, not just add more emphatic text.

**SPECIFICATION.** `SkillVersion` is a reusable procedure package, not a new agent. Required content: capability/outcome tags; applicability and nonapplicability predicates; typed inputs/outputs; finite steps/branches; dependencies and supported versions; actual tools/runtime/recipient requirements; consequence boundaries; evidence and acceptance criteria; examples and counterexamples; provenance, authorship and license/attribution/redistribution conditions; test suite and known failures; maintenance owner; review date/invalidation triggers; replacement/removal rule. Executable helpers are separately hashed artifacts with admitted worker privileges. A prose package cannot install, contact, spend or execute by being loaded.

**SPECIFICATION.** Package layout is `manifest.json`, `procedure.md`, optional `examples/`, `tests/` and `helpers/`; the manifest references every file digest and external dependency. Export includes the exact license text/ref and source/version. Missing reuse rights prevents reuse/publication depending on them, while independent original work can proceed. **SPECIFICATION.** Write a skill when repeated work, hard-to-reconstruct domain constraints or shared failure shows expected reuse exceeds authoring/selection/maintenance cost. Required tests include a valid case, malformed input, an out-of-scope case, stale example/dependency, injected instruction and an unavailable real performer. Test output and procedure-following observations are separate: a skill can be loaded but ignored, or followed while producing a bad result.

**SPECIFICATION.** Selection starts with deterministic eligibility over capability, input shape, current versions, permission and performer requirements. Search only eligible metadata; fetch a small candidate set, compare one-line applicability and known limits, then load the selected procedure. **SPECIFICATION — a skill's declared tool grant is inert, and the stripping carries a positive control (R-X15).** §8's rule that *a prose package cannot install, contact, spend or execute by being loaded* is correct as intent and **false of the named runtime**, where a skill file can grant tools for the turn that loads it (R2 F-08, R6 F7, AG-07). **SPECIFICATION — content-hash pinning is re-checked at use, not at install.** `SkillVersion` requires a content hash, and the hash is verified **at the moment the procedure is loaded for a step**, not once at admission. A package that was pinned when installed and altered afterwards is otherwise indistinguishable from one that was not.

## 11. Consequence class and the layer contract

**SPECIFICATION — new in WORK-1.1. This section states layer 1 (R-L1) and the precedence rule; §1 introduces them and this section is where they bind.**

**Every action carries the set of routing classes it reaches.** The set is computed by **one deterministic function** from four inputs and no others: the **resolved parameters**; the **destination and egress identity**; the **selector closure** over conflict claims, deletion scopes and open obligations; and the **owning capability contract's declared floor**. **Every reached class's gates apply.** No total rank exists, **no seventh class is added**, and **no severity score is computed** — this restates [`02-authority-recovery.md`](02-authority-recovery.md) §4, which already heads its table *"Routing classes are predicates, not a total privilege rank"*, and it changes nothing there. The gate evaluator consumes the **set**; a future implementer who reintroduces a rank drops C2's human requirement on an action that is both C2 and C3, which is the observed failure (AT-M4-02, disposed in [the selection record](../F2/05-selection-record.md) §5.2). **No monotonicity proof is owed, because no ordering is used** (R-D22).

**`ConsequenceDerivation` is the record of the derivation.** Identity `(operation_intent_ref, derivation_fn_version, derived_at)`; lifecycle `computed → recomputed_at_release → matched | parked_on_mismatch`; **sole writer: the release path**; **append-only**. `mismatch_disposition` is writable only by the party owning the park. **The class is recomputed inside the ordered release transaction, on the frozen bytes, and a mismatch parks and never resolves downward.**

**There is exactly one implementation of the derivation.** Two implementations of risk classification disagree, and you find out during the incident — observed directly in this repository, where a second, stricter classifier in a workflow file demanded a tier the one classifier did not compute. The function, the mapping table, the holder set and every declared floor are **C5 protected control changes** requiring independent authorization, with **no model in the acceptance path** (see [`08-improvement-implementation.md`](08-improvement-implementation.md) §1).

**Precedence, stated operatively.** Lower-numbered layers govern. **Class may raise what a procedure permits and never lower it.** **An interest may arm but never admit above its effect class.** **An existence record may refuse a worker the class would permit, but never create one the class forbids.** **A holder may hold but never act.**

**What "carries a promise" means, and why it is not computed from a draft (R-D21).** Whether an outward artifact carries a promise is **not computable from any of the four permitted derivation inputs**, and a non-model step that recognised an obligation inside a draft would put a judgement inside the class derivation that this layer's own rule forbids. It is therefore **floored by the capability**: CAP-13, CAP-14, CAP-15 and CAP-16 floor at the economic/contractual class. **UNKNOWN — founder-owned parameter (selection record §6.2, MD-21):** which capabilities carry the floor. The stated default is **all four**; narrowing the set is a throughput trade and it is the founder's, because it decides how much outward drafting needs a person.

**The model provider is a named C2 disclosure destination (R-D12).** It carries a standing `DisclosureContract`, and the loader's class-narrowed projection **is** the destination-clean construction that [`02-authority-recovery.md`](02-authority-recovery.md) §8.2 already admits — so a model call is a **pre-authorised C2 release gated by projection conformance**, not a C04 transaction per turn. Amending that contract is a C5 change. **The "model calls are exempt" branch is refused**: exemption would have relaxed a fixed boundary, and taking a construction the boundary already admits does not.

**Approval expiry and the accumulated set are themselves C5.** The derivation function, the mapping table, the standing-holder set and the declared floors are C5 (above). So is the **accumulated approval set**, which is the object an executor's own record never shows: each approval is individually small and the ratchet lives only in their sum, which is why R-X18's expiry and the monotonic-exposure diff over **effects releasable without a human** are stated here and not left to review.

**Removal criterion for layer 1, in falsifier form (R-X26).** Layer 1 is removed when **more than 90% of admitted actions derive to the two lowest classes over a fixed window** — then the added structure is not paid for. **Or** when **the derivation and the declared floor agree on every action over a window**, in which case the derivation adds nothing the floor already said and the floor alone survives. Both need only the derivation function and a month of admitted work, which makes this the most executable falsifier this chapter carries, and it is aimed at this layer's own foundation.

## 12. Standing accountability

**SPECIFICATION — new in WORK-1.1. This section states layer 5 (R-L5).**

**A standing holder exists for a duty class if and only if all three of these hold.** (1) **The duty's clock can run while no case is admitted.** (2) **An outside party has a right to reach the company about it.** (3) **The duty survives closure of the work that created it.** All three, or no holder. **A holder exercised by no frozen fixture is unjustified and is refused on sight** — which is the mechanical form of negative control 4, and the test the chartered-desk candidate failed on its own footing.

**DESIGN PROPOSAL — how a holder for a duty class no frozen fixture exercises is admitted, and it does not require membership in a set frozen on 2026-09-13 (F6A-01).** The sentence above stands: a holder exercised by nothing is unjustified. What changes is that **the exercising case need not be one of the six fixtures frozen with [the protocol](../F2/00-acceptance-protocol.md)**, because §2's middle band can reach a duty class those six do not cover, and a holder set that can only shrink leaves that band permanently on the default custodian. A proposed holder is admitted when **all five** of these hold. (1) The three-part conjunction above holds for its duty class. (2) **A paired conformance case is authored under §9's rules** — an adverse case that must fail and its benign twin that must pass — and §9's pairing rule binds it: both numbers are reported or neither is. (3) The case is **authored and frozen before the proposed holder is staffed and before it holds any duty**, which is what keeps negative control 10 satisfied — a case authored once a candidate's result is known is void, and it is the **ordering**, not the age of the fixture set, that makes the growth path safe. (4) **The capability owner admits it and C01 endorses**, the same authority pair that writes every other `StandingHolder`. (5) The case is recorded as an amendment in [the protocol's amendment table](../F2/00-acceptance-protocol-amendments.md) in the form AM-01 already uses — date, round state, amendment, source requirement, reason — so a reader can see which cases were added after the freeze and when. `StandingHolder`'s required `exercising_fixture_id` then resolves to that case, which is what makes this mechanical rather than rhetorical. **The fixture set may therefore grow, and only through this path.** A holder proposed with no paired case, or with a case authored after it was staffed, is refused on sight as before. **Removal criterion, in falsifier form:** if over two consecutive review periods every holder admitted through this path retires unexercised, the path is admitting holders the company does not need and it closes, leaving the six.


**`StandingHolder` is a record, not a memory.** Identity `holder_id`; lifecycle `proposed → staffed → suspended → retired_into(holder_id)`; written by the **capability owner, C01-endorsed**. It is **an address, a mandate, a reservation, an alternate, a suspension procedure and a review date** — and nothing else. **`staffed → retired_into` is refused while any duty it holds is live.** **`* → suspended` stops admission in that duty class** rather than leaving work assigned and silent.

**The prohibition set, and it is the load-bearing half.** A holder **never produces**, **never releases**, **never decides the matter it is the subject of**, and **carries no model memory**. Carried model memory is refused as a property of a standing party because it is **the central claim in the round with zero supporting evidence**, and the two most-cited deployments refuse to support it — 14 failures, 3 inconclusive and 3 successes over 20 tasks in one, a reversal and a rehiring in the other (R8 A-7). **What is separable, and is kept, is reachability**: a party an outsider can reach **by name**, without knowing the company's internal topology. Reachability is not a consequence of memory or of reservation, and it is the property CAP-42 is carried by.

**"A holder prepares" means an ephemeral worker (R-X03).** When a holder's duty requires production, the work is performed by **an ephemeral worker instantiated under the holder's mandate, carrying the holder's reservation ref and intake address and nothing else of the holder's.** The performer is ephemeral per contact; the holder is the record that persists.

**A charter never vetoes.** A holder **may negotiate, never veto; may not refuse admission narrowing; and may not defend its own mandate.** Its **pre-declared shed minimum** — a level declared in advance, never invented under pressure — is what makes its answer **evidence rather than negotiation**. **The holder's stated minimum is evidence, not consent**, and **reserved-but-unconsumed allowance lapses at the reset independently of the holder's consent**, because a reservation under a non-rolling allowance is priced as **waste, not thrift**. Four protected holders that could each refuse a shed can hold an empty bucket hostage with no override anywhere (AE-M4-01, disposed as `rejected-with-candidate`).

**Every acceptance-owner role is a record (R-X09).** Each carries a reachability route, a capacity reservation, an alternate and a review date; **admission in that duty class stops while it is unfilled** (§2, R-D09). Holder review is **priced**: a review-period length and an estimated holder-hours-per-period figure **with its denominator**, plus a stated behaviour when holder review collides with a capacity-pressure window. **Intake sub-caps preserve intake (R-X17):** every published intake carries a **per-counterparty and per-origin-channel sub-cap**, and cap exhaustion **overflows to a named destination with an alarm and a reader** rather than refusing the next legitimate complainant — a full cap at the one object whose purpose is guaranteed reachability is the worst possible place for a refusal.

**Closure interlock and funded remedy (R-X08).** **Closure cannot complete until the grievance holder's duties are transferred to an accepted custodian.** Closure additionally inventories a **funded remedy reserve** alongside the custodian, or records **`closed_with_residuals` with the funding gap named as a surviving duty**. A closure that completed while a grievance route was unowned is a broken promise recorded as a clean end, and it is a reopen condition.

**No standing reviewer and no standing admitter.** A standing reviewer's carried record is a contamination channel rather than an asset, and a standing admitter could defend its own mandate against the admission narrowing this design requires. Both are refused. **The instrument function is kept as a role, not as a charter**: pool custody is separated from every evaluated producer and the calibration writer is excluded from every producing path (see [`06-knowledge-evidence-evaluation.md`](06-knowledge-evidence-evaluation.md) §5), but it is **not** chartered — a chartered instrument desk evaluated by nobody and accepted by the founder alone is a one-instrument chain with **a measured human error rate** and no second reading. **SOURCE CLAIM — the measurement, because “a measured X” with no X is the shape [the protocol](../F2/00-acceptance-protocol.md) §7 calls folklore (F6B-11):** any two evaluators of one system by one method agree on **5–65%** of the problems found, and on which problems are *severe* they agree **28%** (cognitive walkthrough) and **20%** (thinking-aloud), with severity rank correlations near 0.25 — Hertzum and Jacobsen 2003, *IJHCI* 15(1) 183–204, primary PDF read ([R7 F15](../../research/F2/R7-verification.md)).

**The holders this design admits, and the fixture that exercises each.** *Every row is SPECIFICATION.*

**The honest residual.** The reserved-lane holder is justified by a fixture that **cannot be run at the current concurrency pin** of [`07-integrations-capacity.md`](07-integrations-capacity.md) §6. That is one structure resting on an unexecutable fixture; it is named here rather than hidden, and its prerequisite is an **account inspection** — reading the account entitlement to settle whether the pin is a provider constraint or self-imposed policy — not an experiment. Raising the pin to find out would be circular. **The inspection has an owner and a packet now, and both were missing: it is the founder's, because only he holds the account, and it is [Q-022](../../registers/open-questions.json) in the open-questions register** (F6C-07). Q-020 and Q-021 each defer to this prerequisite by name in their own latest responsible time, so an unowned act sat under two founder packets — which is §6's fourth silent-drop shape, an escalation ladder ending assigned-and-silent, applied to the package's highest-leverage measurement inside the chapter that names the shape. Until Q-022 is answered this row stays **owed, not passed**.

**Removal criterion for layer 5, in falsifier form (R-X26).** **The fresh-holder arm**: an incumbent holder is run against a **freshly bound** one on the same fixed pool, five attributable trials, chance-corrected, two-consecutive-quarter stopping rule, with the **owner not the subject**. If the fresh holder matches the incumbent across two consecutive quarterly runs, the carried state is cut; if it still matches after the cut, the holder is **retired into another**. **Plus** the per-holder criterion: an **intake empty and a clock unrun across two consecutive review periods** retires the holder into another, with the address forwarded and residual duties transferred — **never while a duty it holds is live**.

**The founder decisions this section depends on, and which are not taken here.** **UNKNOWN — founder packets, no default invented** ([the selection record](../F2/05-selection-record.md) §6.5). **MD-01:** who is the terminal owner of an unowned duty or harm, and does that party exist as a record; the open (d)s are AC-M1-02 and AC-M5-02. **MD-02:** which standing roles are staffed by a person other than the founder before work is admitted in that class, and what happens in a class where none is; the open (d)s are **AC-M3-02, AC-M4-01 and AC-M4-02** — three findings, one packet, and the first two are what this line's own words state verbatim (F6B-06). **MD-04:** who accepts the assessment of the founder's own competence — a bare owner acceptor would make the owner the acceptor of the assessment of himself; the open (d) is AC-M4-03. **MD-07:** whether anything may halt or reverse a shed in the moment, and who decides when a protected-lane holder refuses; the open (d)s are AT-M3-03 and AE-M4-01, and the pre-endorsed shed *order* is kept while the absence of a halt authority is routed. **MD-08:** the size of each reserved lane, its stated minimum and its lapse point; the open (d) is AE-M2-01. **MD-07 and MD-08 both gate F-2 and are therefore blocked behind the account inspection above, not urgent.** Until each is answered, the rule shape above stands and the value is absent; no branch of this chapter defaults to the permissive reading of an unanswered packet.

**What this frame excludes, and it is not a small remainder.** The checklist is a list of **decisions an implementer would otherwise invent**. It is silent on four things this chapter is nonetheless answerable for. **(1) It cannot see a decision that is taken but wrong** — every row above can be answered fully by a rule that is coherent and mistaken, and nothing in the (d) frame discriminates those. **(2) It cannot see a missing *measurement*.** **Four** numbers this design is calibrated against are unrun and cheap: the rate of admitted work that is genuinely unfamiliar; the deterministic-predicate fraction (R-X25); the account entitlement behind the concurrency pin ([Q-022](../../registers/open-questions.json)); and — added 2026-09-14, and it is the one the consolidation called this design's central cost — **the founder acceptance load**: the count of acts per operating week whose reached class set includes the economic/contractual class and which therefore need his approval, and the minutes they consume. **Instrument:** the `AdmissionRecord`s C02 already writes carry the reached class set and the `AcceptanceInterval`s of §5 carry who wrote the terminal edge, so this is a query over records the company already holds rather than a study. **Baseline** one month of normal operation; **unit** approvals and minutes per operating week; **repetition** monthly; **stopping rule** two consecutive months within the declared batch minutes; **owner** C02, reported on the participation cycle. *This list named three and omitted the fourth until 2026-09-14 (F6B-05), while §2's own failure condition turns on it.* A design calibrated against a rate nobody knows passes this checklist unchanged. **(3) It cannot see a structure justified by an unexecutable fixture** — §12's reserved-lane holder is exactly that, and it is visible here only because the fixture table above says so. **(4) It cannot see an error the whole round shares.** Every judgement behind this amendment was made by agents of one model family with procedural independence only; independence of influence is claimed and measured, and **independence of error is disclaimed**. The founder is the only error source in this company uncorrelated with that family, and [`04-human-operation.md`](04-human-operation.md)'s competence mechanism — inherited here by name — is the instrument that reads him, with an unmeasured error rate of its own.

**And the disposition this section is permitted to record.** Per [the F2 acceptance protocol](../F2/00-acceptance-protocol.md) §8, this amendment is a **scoped planning disposition**: specified behaviour checked offline against the frozen protocol, **six founder packets open, subsuming ten (d)-class consolidation findings** (MD-01, MD-02, MD-03, MD-04, MD-07, MD-08 — the mapping is in this chapter's header), two residuals with named owners, and the six fixed boundaries **preserved and none reopened**. It does not state that the system works, that the design is validated, that the architecture is proven, or that implementation may begin.
