are.** In the session's own worktree it dies at **step 8**, `test:registration`, with `EPERM` writing

```
for s in check:dispatch check:memory check:map check:warroom test:hooks test:budget test:lenses \

```

**2. Three hooks match command text instead of parsing it. All three fired.**

| Rule | Predicate | What it actually does |
|---|---|---|
| `git checkout --` | `git\b.*checkout\b.*--\s+` | Evaluated against the **whole multi-line command flattened to one line**. Proved: `git`+`checkout` on line 1 and `-- ` on line 3, nothing matching on any single line — still blocked. Any script with a `checkout` token anywhere and a `-- ` anywhere, at any distance |
| `npx` | `(^\|[;&\|]\s*)(npx\|bunx)\b` | Blocks the **word appearing in a string you are writing**, not only a command you are running |
| `Write`/`Edit` outside project root | project-root containment | Refused — while **Bash writes there freely**, and `allowWrite` explicitly grants `/private/tmp/claude-501` |

The third is not a false positive, it is a **disagreement between two controls about the same path**.
Every lane this session edited its clone through Bash because the Write tool would not. Either the hook
should permit what the sandbox grants, or the sandbox should not grant it. Nobody has decided which, and
until someone does, "Write is contained" is not a true sentence.

**Workaround for the first, which is not a bypass:** keep `sparse-checkout` in its own Bash call and put
no `-- ` in it. The rule's stated intent — don't discard uncommitted changes — does not cover a clone.

## 3 · The two things review caught, both overclaims rather than broken code

**The check-run is not unforgeable in this repo's threat model.** `qa-lead-pass.yml` triggers on
`pull_request`, not `pull_request_target`. For a **same-repo** PR — this project's only flow, since the
worktree protocol pushes straight to `origin` — GitHub executes the workflow definition **from the PR's
own head** with the full declared `permissions:`, including `checks: write`. So a PR can rewrite the
verdict step and mint its own check-run. It is still a real improvement: forging now requires modifying a
workflow file, an `irreversible`-tier change, where the old author grep required only writing a line into
your own session file. **The control that would actually close it is branch protection or CODEOWNERS on
`.github/workflows/**` — a repository setting, and the founder's.** Not reproduced live; there is no
network in the sandbox. Grounded in documented `pull_request` semantics.

**A citation that did not support its claim, which the linter cannot catch.** `SANDBOX.md` asserted these
were credential stores for "the other two model families this repo invokes for independent review."
The repo invokes **none**: `TARGET-ARCHITECTURE.md` decision 5 chose Codex **over** Gemini and Codex is
uninstalled; `grep -ci gemini .claude/ledger/index.json` returns **0**; both `verified_by: judge` claims
