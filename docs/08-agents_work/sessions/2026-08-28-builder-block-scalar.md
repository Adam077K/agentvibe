# A block scalar is content, and the parser was reading it as a stream of scanned lines

**The root cause is a whole-document pre-pass, not a line-level bug.** `scanLines()` normalises every line of the document before any structure is known: it drops blank lines, drops `#`-first lines, runs `stripComment` on every line, right-trims, and strips all leading indentation. All five are correct for a plain scalar and all five destroy a block-scalar body, which the `>`/`|` branch then reassembled from that already-normalised stream. **Two of the five delete the line from `lines[]` entirely**, so the body was not reconstructible from the scan's own output — which is why the fix reads back into the raw source and every scanned line now carries its raw index. Five of SIX content losses fixed: a `#` preceded by whitespace truncated the value; a `#`-first line vanished; a blank line vanished, and in `>` that destroys the fold boundary so `alpha\nbravo` became `alpha bravo`, a different sentence; relative indentation flattened to column 0; trailing whitespace was stripped. **The sixth is named and NOT fixed**, because it is upstream of this fix and not reachable from it: `scanLines` runs `stripComment` over block-scalar bodies too, so an odd apostrophe throws `unterminated quote` and takes the **whole document** with it, not one value. `.claude/agents/reviewer-readonly.md` frontmatter is the live instance — unparseable by the repo's only YAML parser, with no live consequence because `schema-lint` reads frontmatter with its own `parseFrontmatter`. This fix makes the block-scalar **value** content; the **admission** decision is still the line scanner's.

**A CRLF fix neither review's brief predicted, and it is wider than the symptom.** Both reviewers found line endings independently. Three candidates measured against js-yaml: doing nothing leaves lone-CR as `"|-\r  a\r  b"` — **the block indicator itself becomes the value**, because `scanLines` splits on `\n` only and a CR-terminated file is ONE line; the narrow `/\r\n/g` fixes CRLF and leaves that untouched; the wide **`/\r\n?/g`, applied once in `parseYamlSubset`**, fixes all three and is what landed. It removes the **condition** — two blankness predicates over one source — rather than a consequence. The live scenario is a contributor committing `gates.yml` with CRLF: a whitespace-looking diff, every one of the 15 `>` values silently carrying interior `\r`, `check:gates` still exit 0, and the printed governance record rendering only the last physical line.
