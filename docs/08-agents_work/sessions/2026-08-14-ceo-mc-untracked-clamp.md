`statusConfigEnv` forces `status.showUntrackedFiles=all` rather than `normal`. Two lines of production change; the rest is the comment saying what the clamp cannot do, and tests covering the space rather than the fix.

**The severity this PR responds to was wrong twice, and the corrections are the substance.** A delta reviewer found that forcing `normal` clamps `=all` *downward*, turning `?? newdir/a.ts` + `?? newdir/b.ts` into `?? newdir/`, which `detectConflicts` then collides across worktrees. The CEO recorded that as a defect PR #35 had **introduced**, and briefed a raise-only clamp. **The author refuted both with a three-way table**, since confirmed independently against git's real default with the setting unset anywhere: `no` → nothing, `normal` → `?? newdir/`, `all` → the individual files. `normal` *is* git's default, so the collision was pre-existing and unconditional; #35 removed an accidental escape rather than creating a defect. Raise-only would have restored that escape for a minority, left the defect for the majority, and made directory-vs-files depend on ambient config. **Forcing `all` is one-directional by construction, because `all` is an endpoint of the domain** — the rule this bug produced, applied to its own source.

**What the fix does not do, stated in the code because the first version of that comment claimed more than it holds.** `all` splits untracked *directories* within one repository. It cannot split a **nested repository** — git reports one as a single entry — so two worktrees vendoring *different* nested repos at `vendor/thing` both render `vendor/thing/` and still collide. **Reproduced through real `detectConflicts`**, logged as #52. `agentvibe` is unaffected only **incidentally**, because it gitignores `.worktrees/`; an incidental mitigation is not a fix and is recorded as an accident of the ignore file.
