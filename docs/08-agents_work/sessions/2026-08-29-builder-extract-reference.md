# The reference extractor measures, and it can kill the rule it was handed
**The valuable half is `--against`, and its negative control passes.** MIT-licensed extractors already exist; a tool that holds a STATED RULE against measured references and reports it REFUTED does not. `min-adjacent-ratio 1.125` — live in `design-probe.mjs` as `MIN_STEP_RATIO` — comes back **REFUTED** against linear + stripe + mission-control, **UNDERPOWERED** against one reference, and **CONTESTED** the moment one reference conforms. An unknown rule kind is `UNSUPPORTED` and exits 2, never a quiet CONFORMS. Four mutations were run: killing REFUTED, the robots refusal, the tracking-extrapolation guard, and the leading usage floor each turn the suite red (3, 9, 3, 3 failures); the restored control was **36/36**, which is the count the mutations were run against — the suite is 37 now, after the refusal-attribution test below.
**Three measurements DISAGREE with the research that commissioned this, and the measurement is what is recorded.** (1) vercel.com's UI band measured as **12/14/16**, ratios 1.167 and 1.143 — it **CONFORMS** to 1.125, so the brief's expected three-way REFUTED is CONTESTED and the test pins that disagreement rather than bending to it. (2) play.grafana.org does **not** ship "12 14 and nothing else" once scrolled — 8 sizes including 11.9/12.6/15.4/16.8/18.2, rem multipliers off a 14px root, so it **violates** the integer-increment rule the corpus was meant to establish. (3) mission-control's ramp carries **six** consecutive +0.5 increments, not seven; the sequence `1 0.5×6 1` is otherwise reproduced exactly from the raw sizes.
**Real data produced confident nonsense three times and each refusal is now tested.** A tracking regression crossed zero at **-8.302px** after passing its r² test (extrapolation outside the measured range → null); a leading peak of **2.75 at 16px carried by 4 of 586 elements** outranked 1.714 at 14px carried by 218 (usage floor → the peak is over sizes the reference uses); a display "ramp" of 24/48/72 covered **3 of 7** measured display sizes and read as tidy (now says what it does not reach). `leading.falloff`/`exponent` are null **always** — the contract names them without stating the curve.
**Legal posture verified by a live refusal, not by reading the code.** `godly.website` → `DISALLOWED (Disallow: /, matched as ClaudeBot)`, **exit 2**, no page fetched. A robots.txt that cannot be read is not permission: 4xx allows, 5xx and network errors refuse. TLS verification is never disabled — one of the two reasons the BrightData scripts are being replaced; the other is a `BRIGHTDATA_API_KEY` that appears nowhere in this repo. `.claude/skills/design-mirror/**` was **not** touched.
**A defect this session found by RUNNING the tool, not by reading it.** Under the armed sandbox the network is denied, robots.txt could not be fetched, the tool failed closed — correct — and then printed *"linear.app disallows this path"*, a **false statement about linear.app** produced by an otherwise correct refusal. `checkRobots` now carries a `reason`: `disallowed` · `unknown` · `no-robots-published`. **A reference capture is a reliable sample of SCALE and a poor sample of USAGE.** Re-capturing stripe.com twenty minutes later moved 144/86 lines and **none of it was the ramp** — identical distinct sizes, identical ui band, identical fit (base 8, +2, 10 steps), identical increments. Element counts, colour tallies and spacing moved. Read the usage floor with that in mind.
**A rule died, and then came back — which is the harness working in the direction nobody wanted.** "No display band" was killed on the evidence that play.grafana.org *"ships 12 14 and nothing else."* That reproduces **exactly** with `--no-scroll` and is **false** with the scroll pass: grafana renders 15.4/16.8/18.2/28 above its ui band. `must-have-display-band` is currently **HELD by 5 of 5**. **Two contract gaps the tokens lane found by reading `seeds.json` rather than my output.** `family: {sans, mono}` was missing entirely and is now derived from what the site itself declared (null when no mono stack is rendered, as on grafana). `consumerRefusals()` names the four things `build-tokens` rejects — ui increment ∉ {1,2}, display increment < 4, and **the band join** — and it fires on a real reference: grafana's 15.4/14 = 1.1 against a 1.111 internal step. **One deliberate departure, flagged not quiet:** they proposed nulling those fields; I keep the measured value and add a `WILL BE REFUSED` note, because their generator never reads this file and nulling a correct measurement to please a validator it does not talk to would make the file lie about the reference.
**THE CURVE IS FITTED NOW, AND NOT ONE REFERENCE OBEYS IT.** The team lead supplied the function `build-tokens.mjs` implements — `lineHeight(s) = peak - (|s-peakAt|/peakAt)^exponent * falloff` — so `falloff`/`exponent` stopped being a schema refusal and became a measurement. Linearised as `log d = log falloff + exponent·log u` and fitted. **The positive control recovers `peak 1.55 · peakAt 16 · falloff 0.62 · exponent 1.1` exactly, residual 0, from data generated by the formula** — so the fitter works. Against the real corpus, **0 of 5 fit inside a 0.1 RMS residual**: linear 0.134, stripe 0.106, and vercel/grafana/docs-stripe carry too few off-peak points. linear.app's leading is not even monotone in distance from its peak (12px sits further below the peak than 10px while being nearer to it), so no curve of this family passes through it. Per the lead's own instruction that a poor fit is evidence about the formula rather than the reference, the parameters go null with the residual named. A test pins 0-of-5 so a reference that later fits is a red test and a decision, not a flake.
