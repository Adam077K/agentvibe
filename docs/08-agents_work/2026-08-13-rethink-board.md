# Rethink Board — 2026-08-13

Thirteen dimensions of the Agentvibe agent harness — first-run, core-promise, legibility, journey-build, journey-gtm, journey-decide, failure-modes, cost-speed, safety, competition, architecture, absences, and the plan — were reviewed by an adversarial three-lens panel (correctness, reproduces, already-known); every surviving finding had to clear all three, and sixteen proposed findings were killed. The method was static analysis, command execution traces against live hook processes, and corpus analysis across 2,126 transcripts / 2.88 GB — no end-to-end playbook dry runs were executed. The most important finding is not architectural and not competitive: `bin/warroom:235,237` spawns every CEO pane with `claude --dangerously-skip-permissions`, a flag that appears zero times in README, CLAUDE.md, or AGENTS.md, making the entire `settings.json` allow-list and deny-list inert during the product's normal operating mode.

---

## The verdict in five sentences

The harness ships with four independent safety P1s that make its permission model inert or bypassable during normal operation, and two of them require only a one-line change to expose. Day one does not work: `bin/init-from-template.sh` substitutes zero tokens and exits with a green checkmark because the instantiation sed ran against the template itself at commit `abf26c2` rather than against a clean template branch, and the npm package ships agents that reference files it deliberately excludes. Eight phases of infrastructure produced 30 session files covering infrastructure and zero covering venture work, a QA gate the authoring agent self-certifies by writing its own `qa_verdict: PASS`, and a claim ledger with zero entries in the user-language or external-fact categories the architecture was built to govern. The architectural core — claim-ledger-as-enforcement-spine — is correct and has no production analog in any surveyed system; none of its correctness has been tested against real work. Phase 9 fleet rollout would propagate a system with active safety holes, a broken install path, and no behavioral validation to eleven projects, in that order.

---

## What eight phases bought

**Load-bearing and good.** The claim ledger design is architecturally correct for its stated problem: per-claim `valid_until` with forced disposition (Refresh / Deprecate / Waive) is the right mechanism for catching silently-rotted operating assumptions. `ADR-001:70-78` surveyed 24 production systems and found no equivalent. The roster collapse from 52 files to 6 engines is correct: 52 agent definitions generate contradiction and drift, 6 do not. `schema-lint.js` as a genuinely enforcing linter — failing builds on schema violations, resolving dead lens references against git history — is real and unusual. The shadow-mode-first promotion discipline is right. The worktree protocol, conceptually, is the right isolation unit.

**Expensive and did not pay.** Mission Control was built before the harness was used for its purpose, against the plan's own written recommendation (`PHASE-8-HANDOFF.md:65-69`). It introduced the repo's first external dependency (Bun), its first non-trivial frontend build, a command-injection RCE caught in review (`PHASE-8A-STATUS.md:14`), and five review rounds on PR3 with three CRITICALS. Four of six planned views have no client implementation. The dashboard is a control plane over a system that has never been used for its purpose.

**Still theatre.** The QA gate parses `qa_verdict: PASS` from a session file the authoring agent writes — demonstrated live when one PR merged green with two CRITICAL findings (`PHASE-8A-HANDOFF.md §0 item 4`). Lens injection is discretionary: agents receive a file path and must choose to open it (`DECISIONS.md 2026-08-12: "an agent must now choose to open a file — which is the definition of discretionary"`). `required_claim_kinds` in the tier map reads as active enforcement and is never evaluated by `ledger verify` (`scripts/ledger.mjs:308-345`). Worktree isolation is documented as `ENFORCED (partial)` (`CLAUDE.md:231`) and enforced by a regex over the agent's own prose, not a runtime boundary. The `--dangerously-skip-permissions` flag makes the `settings.json` permission model inert for every CEO pane the launcher starts.

**No dry runs.** This review analyzed documents, code, and execution traces against live hook processes. It did not run a playbook end to end, did not fire the claim-source resolver against live web content, did not execute a full session through the rebuilt harness, and did not observe lens injection from session start through a downstream engine. Every "never fired" finding is sourced to a document or a `grep -rn` result; if a session ran a stage outside this worktree and was not recorded in `docs/08-agents_work/sessions/`, that evidence is invisible to this review.

**Single model family.** All findings were generated and adversarially reviewed by Claude Sonnet 4.6. A different model family would weight the architectural findings differently, particularly the framing-layer value argument and the cost-speed projections. The safety findings are code-level and would not change. The legibility findings are vocabulary-level and would not change significantly.

**The system reviewing itself.** Documents the system produced — `PHASE-8A-HANDOFF.md`, `DECISIONS.md`, `AGENT-SYSTEM-REBUILD.md` — served as both evidence and the evaluated subject. The adversarial review killed sixteen findings; a reviewer outside this codebase might have applied the three lenses differently, particularly the "already-known" lens, which requires not just that a fact is named in the record but that its consequence was drawn. `AGENT-SYSTEM-REBUILD.md:427` names this honestly: "Self-review is circular by design."

**Sixteen killed findings.** The panel killed findings on three grounds: six on correctness (the causal chain broke at a specific step), six on reproduces (no concrete founder path to the harm existed), and four on already-known (the record had drawn the same consequence). Each kill was defensible under the stated lenses. The kills that raise the most interpretive uncertainty are the "already-known" kills — they require the record to have drawn the consequence, not merely named the fact. Two findings were killed as "already-known" where the record named the cause but not the specific severity of the outcome; those could be re-examined.

**External data.** Competitive and cost claims rest on sources that cannot be verified against the codebase: the Anthropic 95% multi-agent statistic, the full 2,126-transcript corpus cost computation, the true 5h-peak output-token figure. These were treated as directionally correct; if any is materially wrong, the affected findings change magnitude but not the remediation direction.
