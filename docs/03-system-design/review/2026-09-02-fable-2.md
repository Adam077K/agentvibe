## 0 · VERDICT

This is the right shape of the system and the wrong first month. The shape — a pack as an argv, a mouth with no
model in it, a register the world writes to, refusals that carry a countable reopen — is the best design in the
building and governs a class of act (publish, send, spend, contact) that no shipped product I could find governs
at all; Routines, Codex, Jules and Devin all terminate at a pull request. The single largest thing wrong is that
the claim the whole thesis rests on — *"a `claude -p` process cannot call a tool absent from its argv… no
network, no credential in env"* — is physics for MCP servers and named built-ins and is **false today for a
maker holding `Bash` on this Mac**: `git push` reaches GitHub through the login keychain, `osascript`, `mail`,
`gh` and `ssh` are on PATH, and `.claude/settings.json` declares no network policy at all, so the only thing
stopping egress is a session-sandbox default the spec does not own and a launchd child may not inherit. Second,
the entire build path forks on a "looking test" whose measured base rate of zero is a misread of its own source
(the founder judged all eleven beeond mockups; the *agent* could not view them) and whose fail branch the spec's
own fuse already implements as a parameter rather than a redesign. Third, Stage 0 spends thirteen landings on
harness before the fourteenth touches a venture, which is the 171-sessions failure the document diagnoses,
compressed to thirty days.

**What survives the attack.** The argv as the policy seam is right and its scope was overstated: physics for
MCP servers and bare-denied built-ins, and it extends to the network layer the moment the pack compiler passes
the sandbox policy on `--settings` (F1) — the thesis is stronger than the spec knew. The mouth with no model in
it survives whole; no shipped product has it. Refusals with countable reopens survive and are the most
transferable idea here. The fuse survives and dissolves the fork (C1). The rung-generated assertion string, the
one-classifier rule, `unresolved ≠ pass`, `no_data ≠ not_checked`, and "a finding about the instrument, not the
work" survive untouched. The register as the centre survives at full scale (R1). The three-count conjunction
survives, better with decay and a probationary level (F13, I6).

**F1 · Ring 0 is not airtight while makers hold `Bash`.** The spec says ring-0 makers hold
`Read Write Edit Bash Glob Grep` with "No network, no credential in env, no MCP" (OS:1058, OS:2257, OS:2269) and
calls argv absence "physics and not policy" (OS:210-214). Measured 2026-09-02 in this worktree:
`git config credential.helper` → `osxkeychain`; `origin` is HTTPS `github.com/Adam077K/agentvibe.git`; a
maker with `Bash` pushes without ever reading a secret because the helper runs as the same uid. On PATH:
`gh osascript mail sendmail npm ssh open shortcuts security` (and `curl`, per my fields lane). The `sandbox`
block in `.claude/settings.json` has keys `enabled`, `failIfUnavailable`, `filesystem` — **no `network` key**
— and the spec never mentions `sandbox.network`, `allowedDomains` or `strictAllowlist` (0 hits). In-session,
`node -e fetch('https://example.com')` → `ENOTFOUND`: egress is blocked by the *session* sandbox default. The
docs say the sandbox applies to Bash and its children (<https://code.claude.com/docs/en/sandboxing>, read
2026-09-02) and are **silent** on whether a `claude -p` child spawned by launchd arms the project's sandbox at
all. The second layer, `pre-tool-use.sh`, is a substring matcher: it blocked my read-only `for b in gh curl …`
loop because the word `curl` appeared as data, and its npx rule (`pre-tool-use.sh:342`) anchors on
`(^|[;&|]\s*)` so `(` defeats it, as the spec records (OS:120-121). A shell with `osascript` can drive Mail.app,
a separate process outside the sandbox that does the networking on the maker's behalf. LOPA would score this
as one-and-a-fraction independent layers, not two. **What the sandboxing page settles, read
in full 2026-09-02** (<https://code.claude.com/docs/en/sandboxing>): *"Claude Code pre-allows no domains by
default. The first time a command needs a new domain, Claude Code prompts for approval"* — so under an
**armed** sandbox in `-p`, with nobody to answer, a new domain is denied, which is the `ENOTFOUND` I measured;
*"the macOS sandbox blocks Apple Events by default"*, so `osascript` and `open` fail with error `-600`; and
*"Effective sandboxing requires both filesystem and network isolation. Without network isolation, a compromised
agent could exfiltrate sensitive files like SSH keys."* Two things the page also settles cut the other way:
**`strictAllowlist` "set in a repository's `.claude/settings.json` or `.claude/settings.local.json` has no
effect"** — it is honoured only from user, managed, or CLI `--settings`; and the escape hatch is live by
default — *"Claude analyzes the violation and may retry the command with the `dangerouslyDisableSandbox`
parameter"* — unless `allowUnsandboxedCommands: false`. Refusal 14 forbids that parameter "in the loop" as a
rule (OS:2718); the setting is the mechanism, and it is not set. So ring 0's isolation is real **only if the
child arms the sandbox** (docs silent for launchd) **and** the hatch is closed, and neither is owned by the
spec today. **Fix, ascending cost:** (a) the pack compiler passes the sandbox policy **on the argv** —
`--settings '{"sandbox":{"enabled":true,"failIfUnavailable":true,"allowUnsandboxedCommands":false,"network":{"strictAllowlist":true,"allowedDomains":[]}}}'`
— which is the only scope where `strictAllowlist` binds and turns "the argv is the policy seam" (OS:214) from
a slogan into the network property; `pack.test.mjs` asserts it; (b) set `credential.helper=""` in every maker
worktree and `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` in the child's env, holding the GitHub credential only where
the mouth lives; (c) an adversarial egress probe as a suite step — from the exact compiled argv, under launchd,
attempt `dns.lookup`, `git ls-remote`, `git push --dry-run` (the keychain path), `osascript`, `open`, and fail
the build if any succeeds (today nothing tries); (d) parameterised grants, `Bash(npm run check:*)`, for makers,
the pack idea taken to its conclusion. Where: §0, §03, §09, Map 1, REFUSES 14. Cost: medium. Confidence: high.
fable-2.
