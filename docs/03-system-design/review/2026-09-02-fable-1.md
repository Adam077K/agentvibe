## 0 · Verdict, five sentences

**It is the system, and it is at the wrong altitude.** The shape — one register of what left and what came
back, one model-free mouth, the physics line, the fuse with a reversible default, an evidence ladder whose
assertion string is generated from its rung, refusals that carry their own reopen command, one writer per
store — is right, and the open-source field has no system with that set (§7). It is 2,826 lines naming 153
paths of which **37 exist and 10 of those are described wrongly** (§1 F5), and it carries the disease it
diagnoses in Part I: a thirty-day path with fourteen landings and forty-plus artifacts in which the second
real exposure arrives on day 20–30 (§4 R3). **The single largest thing wrong is the physics claim:** the
compiled argv narrows with the one flag that restricts nothing, the "second layer" is inherited settings a
maker holding Bash can discard in one call, and both measurements behind the `MEASURED` label were taken
inside a session rather than under launchd — so every "safe by construction" sentence rests on a label the
document's own line 181 would call a defect (§1 F1–F4). Fix the seam with the vendor's own flags, cut Stage
0 to the demand test plus a hundred-line loop plus a tap that is a program, and do not write the rest down
again until one real mission has run through the crude version.

## 1 · FIX — wrong, contradictory, unbuildable, or unsafe as written

Ranked by consequence. **cost** = to fix in the document or the first code. **conf** = my confidence.

### F1 · The compiled argv uses `--allowedTools` as the narrowing flag. It restricts nothing.
- **Where.** §0 line 213–214 ("`--disallowedTools Bash` … `--strict-mcp-config` … The argv is the policy
  seam"), §02 line 329–335 (the compiled argv: `--allowedTools "<explicit list>" --disallowedTools
  "<explicit list>"`), Map 1 line 2257 (makers: `claude -p --allowedTools "Read,Write,Edit,Bash,Glob,Grep"`),
  §09 line 1153 and Part IV row 2 line 2727 (the assumption is *titled* "`--allowedTools` produces ABSENCE").
- **Why.** `claude --help` v2.1.258 (this machine): `--allowedTools` is *"Comma or space-separated list of tool
  names to allow"* and `--tools` is *"Specify the list of available tools from the built-in set"*. The
  cli-reference page (https://code.claude.com/docs/en/cli-reference, 2026-09-02) is explicit: *"Tools that
  execute without prompting for permission … To restrict which tools are available, use `--tools` instead"*,
  and the Agent SDK page says *"This does not restrict Claude to only these tools."* *(An earlier draft
  attributed the docs sentence to `--help`; the audit lane caught it.)* Landing 2 (2515) names M3 —
  `--disallowedTools` — as the go/no-go for packs-as-argv while the compiled argv never uses that flag to
  narrow a built-in: the probe and the shipped flag differ. **Measured (argv lane), reading the `system/init`
  roster, not model self-report:** `--allowedTools Read` → 30 built-ins and 210 MCP tools present, including
  Bash, Task, WebFetch, Workflow and `mcp__higgsfield__tiktok_publish`. `--tools Read,Write,Edit,Bash,Glob,Grep`
  → exactly those 6 built-ins, Task and WebFetch gone — **but 154 MCP tools survived**; add
  `--strict-mcp-config` → 0 MCP, `mcp_servers: []`. `--disallowedTools 'mcp__*'` removes the tools but
  **14 servers still start and hold their credentials** (probe F).
- **Consequence.** Under the argv as written, Map 1's makers hold everything a default `-p` child holds. The
  only measured half of the claim (`--disallowedTools Bash` → `BASH_UNAVAILABLE`, frame-v1:269) is true and
  is about a different flag. The `pack.test.mjs` rule at line 372 ("denied names appear in no argv") tests
  the wrong invariant: the right one is *`--tools` names the built-ins, `--strict-mcp-config` is present, and
  `--mcp-config` names only the pack's servers*.
- **Fix.** `--tools <list> --strict-mcp-config [--mcp-config $TMPDIR/pack.json]`. One line in `pack.mjs`, one
  test. Rewrite §0, §02, §09, Map 1 and assumption 2 to name `--tools`. **cost S · conf high.**

### F2 · The "second layer" is inherited settings, and a maker holding Bash drops it in one call.
- **Where.** §09 line 473 ("A second layer refuses a dangerous write in-session · `pre-tool-use.sh` exit 2,
  untouched"), 1118 ("A second layer exists under the argv"), 1124 ("The seam is argv absence plus
  `pre-tool-use.sh` exit 2, untouched"); §11 line 1392 (assumption: hooks fire under launchd, half measured).
- **Why.** Hooks, `permissions.deny`, `sandbox.*` and `denyRead` all live in user/project settings, which a
  child loads from its cwd. **Measured (argv lane):** a `claude -p` in the repo cwd fired 3 `SessionStart`
  hooks; the same command with `--setting-sources ""` fired **zero** and its `permissionMode` fell from `auto`
  to `default`; `--bare` likewise fired zero. Docs (permissions, settings pages, 2026-09-02): only **managed
  settings** survive argv — *"Nothing you set overrides them."* A maker with `Bash` can therefore run
  `claude -p --setting-sources "" …` and obtain a grandchild with no hook, no sandbox, no deny set, and it
  authenticated (the probes ran from inside this sandboxed session). Also: the frame **measured** that
  *"Under launchd it runs outside the hook"* (year-one-frame-v1:135) and the spec dropped the sentence —
  `grep -c 'outside the hook' STARTUP-OS.md` → 0.
- **Consequence.** "Layer two" is real for the founder's interactive session and absent for the loop's own
  process, which is the one it was written for. The Strategist's dissent (`strategist:R2:P1`, r01:410) said
  exactly this and the spec ignores it (`grep -c 'who initiated'` → 0).
- **Fix.** Three parts, and the first two are vendor features: (a) a managed settings file at
  `/Library/Application Support/ClaudeCode/managed-settings.json` carrying the deny set,
  `allowManagedPermissionRulesOnly`, `disableBypassPermissionsMode`, `disableAutoMode` and the sandbox
  network `strictAllowlist` — the only tier a child's argv cannot clear; (b) `--restricted` on every child
  (v2.1.248+: *"loads only managed settings and `--settings`"*, confines file tools to the working
  directories, refuses `bypassPermissions`); (c) decide what Bash a maker holds — see C2. **cost S–M · conf
  high** for the leak; the managed-settings remedy is a founder act (it is outside the repo).

## 2 · CHANGE — same goal, better mechanism

### C1 · Compile every child with the vendor's containment flags, and put the deny set where argv cannot reach.
```
claude -p --restricted --model <id> \
  --tools "Read,Write,Edit,Glob,Grep[,Bash]" --strict-mcp-config [--mcp-config $TMPDIR/pack-<id>.json] \
  --permission-mode dontAsk --max-turns N --max-budget-usd C \
  --add-dir <worktree> --output-format json --json-schema <return.schema.json> \
  --settings '{"sandbox":{"enabled":true,"failIfUnavailable":true,"allowUnsandboxedCommands":false,
               "network":{"strictAllowlist":true,"allowedDomains":[]}},"hooks":{…},"permissions":{"deny":[…]}}' \
  --append-system-prompt "$(node scripts/loop/prompt.mjs <task>)"
```
plus a **managed settings** file carrying the same deny set, `disableBypassPermissionsMode`, `disableAutoMode`,
`allowManagedPermissionRulesOnly`. `--restricted` makes argv the owner of configuration (it ignores
user/project/local); managed settings are the tier no argv clears. **Measure before relying on it:** whether
`--settings` carries hooks under `--restricted`; whether `strictAllowlist` set via `--settings` binds (docs say
project settings cannot set it; user/managed/`--settings` can). **cost S–M · conf high** on the flags, medium
on the two unmeasured interactions.

### C2 · Decide what Bash a maker holds. Three options, and the spec picked the widest without saying so.
- **None.** Makers hold `Read Write Edit Glob Grep`; the harness runs `npm run check`, the oracle, the
  screenshot. This is already the spec's own shape for the oracle (936: "`code` runs `npm run check`" from
  the harness). Kills F2's re-exec leak by construction. Cost: no mid-move test runs.
- **Whitelisted.** `--tools Bash --permission-mode dontAsk --allowedTools "Bash(npm test)" "Bash(npm run check)"`.
  The permissions doc (2026-09-02): *"Claude Code is aware of shell operators, so a rule like `Bash(safe-cmd *)`
  won't give it permission to run `safe-cmd && other-cmd`. The recognized separators are `&&`, `||`, `;`, `|`,
  `|&`, `&`, and newlines. A rule must match each subcommand independently."* Exec wrappers (`watch`,
  `setsid`, `find -exec`) are never prefix-approved. This is a real whitelist; the `( npx --version )` finding
  is about the **hook's** string matcher, not this one.
- **Full Bash** (the spec, 388, 2257). Then F2 is live and only managed settings + the sandbox stand.
**Recommendation:** none for `web-feature` in year one, whitelisted when a done-test needs a mid-move
command. **cost S · conf high.**

### C3 · Replace the hand-rolled HMAC chain with Biscuit (Ed25519).
- **Where.** §16 1813–1816, Map 5 2407–2408: "HMAC over those caveats … any holder may append one and nobody
  can remove one."
- **Why.** With HMAC the verifier holds the minting secret, so **a compromised mouth is a minter**, and Map 1's
  separation of `minter` and `mouth` into different processes rests on them not being the same authority.
  Biscuit v3.3 (Eclipse, Apache-2.0, seven implementations): the mouth holds only the root public key;
  *"cannot remove existing blocks without invalidating the signature"*; `sealed` forbids further attenuation —
  the leaf warrant. Macaroons (2014) is what the spec describes, verbatim; stop calling it "macaroon-style".
  Caveat from the audit lane, accepted: on one Mac under one uid a compromised mouth reads the key file
  whatever the algorithm, so Ed25519 buys real separation only when the mouth is off-box or on its own uid —
  one dependency now that removes an unverifiable assumption later. **cost M · conf high** (open-source
  lane; design judgement mine).

### C4 · Liveness by world-effect, not by token count.
- **Where.** 268, 1601–1603: `stalled` = output tokens since the last durable artifact; 269: `stuck` = three
  distinct approach hashes.
- **Why.** Vending-Bench (arXiv:2502.15840): the meltdown is verbose *and* inventive (FBI → legal counsel →
  "quantum nuclear legal intervention"), and failure is uncorrelated with context fill (r = 0.167). Both
  meters read **green through the entire failure** — tokens flow, approaches differ. Project Vend 2: *"forcing
  Claudius to follow procedures"* helped; a supervising CEO agent made it worse.
- **Change.** `stalled` = no change in a world-observable (worktree tree hash, staged dir, `EXPOSURES.yml`)
  since the last checkpoint; `stuck` = N moves against one falsifier with no movement in it. Keep the token
  meter as the *cost* brake it actually is. **cost M · conf high.**

### C5 · The founder's tap is a program from day one.
- **Where.** 486–487 ("a person reading a row and tapping"), Map 4 2396 ("Year one applies tests 1, 3 and 4 and
  cannot apply 2 and 5").
- **Why.** In year one the one component performing every outbound act is the one component with zero checks
  on it, and Stage 4 (2621) is the first time any of Map 5's eight checks executes. `bin/tap.mjs` runs the
  subset that exists today — artifact exists and sha256 matches the staged row · `not_before` passed · no
  `NEVER-SAY` pattern · counters under ceiling — and the founder's act is the *last* check. Stage 4's mouth
  becomes "a credential handed to a program that has already refused a hundred times". The Stage-3 drill
  (2618) has something to drill from week one. **cost S · conf high** (other-fields lane; I rank it first of
  its thirty).

### C6 · Bill the loop to an API key; the rope changes unit, and `usd_per_day: null` must not refuse the loop's own spend.
- **Where.** Decision 8 (162), §13 1600–1602 (`rope_fraction: 0.6`, account-wide), board "could not resolve"
  item 4 (r01:532).
- **Why.** Authentication docs (2026-09-02): *"In non-interactive mode (`-p`), the key is always used when
  present"* — `ANTHROPIC_API_KEY` outranks subscription OAuth. Set it in the launchd job's environment only and
  the loop never touches the founder's 5-hour window. The board's unresolved item has a documented answer.
  Cost at 40 moves/night on Sonnet 5 ($2/$10): **$74/month** counting each move once, **$147** if six tool
  turns re-send context, **$558** with a cold cache — the API-key cache TTL is 5 minutes and moves are 12
  minutes apart, so pay the 1-hour cache write ($4/MTok) or accept C. `--max-budget-usd` then caps something
  real (on subscription auth it caps a notional list-price figure nobody is billed). `--bare` is a trap: it
  guarantees no OAuth fallback and skips every hook.

### C8 · `decide()` as a pure function with an injected clock, returning the ranked eligible set and a cursor.
- **Where.** 250 (`next.mjs` pure, prints its arithmetic), 253 (one move per lane per tick), 1336
  (`StartInterval 300`).
- **Why.** Dagster's `evaluate_automation_conditions(defs, instance, evaluation_time, cursor)` is exactly this
  shape, with the daemon a `while True` around it. Returning the ranked set and acting on the head prints the
  ranking into the record, keeps the single writer, and removes the cost the open-source lane measured: at one
  move per 300 s tick, saturating five cold lanes takes 25 minutes. A crash between decide and write leaves the
  old cursor intact. Also: launchd `StartInterval` **drops** an overlapping firing rather than queuing it
  (`man 5 launchd.plist`), which is the real reason the shape is safe and a better sentence than the one at
  1312–1313 about a circuit breaker "the reference implementation everyone copies does not contain" — that
  implementation is unsourceable, and `KeepAlive` is throttled to one spawn per 10 s (`LAUNCHD_MIN_JOB_RUN_TIME`),

### C9 · Retirement by self-test beside retirement by disuse.
- **Where.** 1412–1413, 1473: zero calls in 90 days → retirement candidate. 476: "unprobed is unavailable" —

- **Why.** Disuse is the bathtub curve's right tail. A check that silently stopped checking is *maximally

### C10 · Generalise `max_meter_latency_s` into a check on every limit.
- **Where.** 1544, 1621 ("above one hour of meter latency it is not a rail") — done once, superbly, for one

- **Change.** `check-observability.mjs`: for every ceiling, limit and rate in policy files, a reading exists, is

### C11 · Fire the cadences on counts, not on the calendar.
- **Where.** Map 6 (2456–2489): one daily appointment, a Friday reckoning, a monthly report — inside a Part IV

## 4 · RETHINK — assumptions the founder and the CEO should reconsider, with the alternative

### R1 · "Physics, not policy" inverts the stack.
The argv is the top layer: the binary reading its own flags. The OS sandbox is beneath it and the spec
already concedes it is *"a guardrail against accident, not containment"* (1138). Managed settings are the only
tier a child cannot clear. The honest formulation, which costs a paragraph and loses nothing: *a tool absent
from the argv is never registered, so there is no call site to reach; the sandbox is the layer beneath that
survives if that assumption fails; and the one tier no process on this machine can argue with is a file the
founder writes outside the repository.* Argv-absence still beats every in-process check in the field —
Roo-Code's four CVEs (process substitution, parameter expansion, `npm install` in the default allowlist, zsh)
are all in-process parsers deciding whether a bash string matches an allowlist. Keep the claim; state it in
the right order. And name the residual the mouth does not close: **branch steering** (NOVA, arXiv:2601.09923) —
an injected artifact cannot make the mouth do an unwarranted thing, but can steer *which* warranted thing is
chosen; `artifact_sha256` is the answer and the spec should say so.

### R2 · The register is the centre of evidence; the operating centre for at least a year is the founder's queue.
§02 line 421–422: "the first venture produces single-digit exposures." Every mechanism that reads the register
— pack-field trust, the allocator, `PL.md`'s cost per surviving exposure, the standing-warrant count — is idle
until rung ≥ 2 readings exist, and §08's own assumption 1 (1034) says the world is "most likely to be false in
a mild, corrosive way." So for a year the centre is empty and the thing that actually runs the company is the
queue of six rows at 07:52. Say so, design the queue as the centre it is (I4, I14, C7), and add the one
mechanism no outside party would let you skip: **reconciliation** against the world's own record (A1). A
register never diffed against an independent record is an account, not evidence — and it is the structural
answer to the machine optimising the register, which the spec fears (2734) and has no answer to.

### R3 · Venture zero eats year one again, and the spec's own diagnosis applies to the spec.
Part I: 171 (174) session files about the harness, none about a customer. Stage 0: fourteen landings
(2514–2527), forty-plus named artifacts, thirty-one test files, and the second real exposure on day 20–30.
The minimal design's declared budget — *"five state files and six mechanisms … Nothing else is built in year
one without a triggered reopen"* (`minimal.md:57–58, 77`) — was not refused; it was not mentioned (`grep -ci
stageable` → 0, and its central falsifier went with it). The cure the spec proposes for built-and-never-wired
— "nothing merges without a caller in the same diff" — is labelled by the spec itself *"the most consequential
wish in this file"* (1479). **Alternative:** Stage 0 is three things — the demand test by hand (landing 1),
a hundred-line loop (mini-SWE-agent scores 65% on SWE-bench Verified in 100 lines of Python; a 2,826-line spec
should be able to say what its 100-line version gets), and `tap.mjs` (C5) — and every other landing gates on
*one real mission has run through it*. The spec's best sentence already says this: *"mission 2 is real … or the
machine has only tested itself"* (1706).

### R4 · "Zero new agent files, ever" throws away measured machinery and blocks D13.
The repo has four registered claims about the `Agent` path — `maxTurns` binds when `agentType` is named, the
MCP grant binds and narrows through dispatch, the hook matcher, nested spawn — and `qa.js` runs eight times and
blocked its author. The spec replaces that path with `claude -p` processes whose narrowing is unmeasured
under the loop's condition (F4), and its "never dispatches through `Agent`" test (377) uses `qa.js` as the
positive control for a rule that makes `qa.js` unreachable from the loop. Meanwhile the vendor's `--agents`
flag defines subagents dynamically from JSON, with per-agent `tools`, `model`, `maxTurns`, `isolation:
worktree`, and Workflows ship `parallel()` with ≤16 concurrent agents — the hand-rolled variation runner
(351) re-implements it. **Alternative:** a pack compiles to *both* an argv and an `--agents` entry; the loop
uses `-p` for the move and the measured `Agent` path for in-move fan-out. Both are argv, neither is a file.
D13's precondition (a) becomes satisfiable. *(I hold this at medium; it reopens the org-chart worry at 781.)*

### R5 · The founder not looking is the normal path, not the failure branch.
Assumption 1 (2726): measured base rate zero; if false, "stop the vision." Every autonomous-company experiment
in the record (§7) failed at the human's *attention*, not at the machine's capability: 97% approval rates,
catch rates decaying by day 8, a $5,000 goal met at $510. Design for absence (C7), bound the queue (I4),
measure the reviewer (I14), and treat a looking founder as the upside case. The spec's Stage-1 fork gets the
diagnosis right and the response wrong: a fatal branch is a plan to be surprised.

### R6 · Harness as product or scaffolding — the dropped founder item decides half the document.
Founder action item 7 (r01:510) — *"changes which of these fifteen decisions are worth taking"* — is gone
(`grep -ci scaffolding` → 0). `bin/fleet-install.mjs` (1,053 lines) already installs the harness into another
project and checks later whether it still has it; Decision 4 says template extraction is "a later question."
The repo has answered the question with code and the spec has not answered it in words.

### R7 · "Nothing is deleted to meet a cap" is an epistemic rule wearing a legal costume.
Right for decisions and claims; wrong for people. The first real person in `people.yml` or an inbound mailbox
brings erasure duties that an append-only, never-expiring store (644, 656, 2288) cannot meet. A retention
column on Map 2 and a deletion program are not a weakening of the memory discipline; they are the same
discipline applied to a store class the spec has not yet met.

### R8 · The spec is right to refuse judge-resolved done-tests, and the evidence is stronger than it claims.
Null-model attack: a constant "Pick me!" scores 86.5% on AlpacaEval 2.0 (arXiv:2410.07137). JudgeBench: the
strongest judge 64% on objective correctness (2410.12784). A production gate flagged 0 of 100 rounds where
humans confirmed 23 defects (2606.10315). Project Vend 2's supervising CEO agent authorised eight times as
often as it denied. Keep refusal 8 forever; cite this.
