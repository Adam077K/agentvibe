# Lane · cognition and tickets · 2026-09-05

## Questions answered

All three, unevenly. (1) Planning and self-check: strong primary evidence from Claude Code's permission-mode docs, Anthropic's agent-building post, Devin's guidance, and three measured papers. (2) Ticket schemas: Linear, GitHub Copilot coding agent and the Claude Code GitHub Action are sourced; Jira, Codex cloud, Cursor and OpenAI Symphony are NOT — I hit the 25-call ceiling. (3) Graded autonomy: Claude Code's six modes and Codex's approval/sandbox grid are the two shipped schemes I could source verbatim. No SAE-style "autonomy levels" scheme was found in any vendor doc I reached.

## Findings — how shipped systems plan, critique, define done, reflect

1. **Plan mode is a first-class permission mode, not a prompt convention.** "Plan mode tells Claude to research and propose changes without making them. Claude reads files, runs shell commands to explore, and writes a plan, but does not edit your source. Except in sessions with bypass permissions available, edits stay blocked until you approve the plan." Entry: "Enter plan mode by pressing `Shift+Tab` or prefixing a single prompt with `/plan`." (code.claude.com/docs/en/permission-modes, accessed 2026-09-05, confidence H)

2. **`AskUserQuestion` is a real named tool with a privileged status.** In `dontAsk` mode, which "Auto-denies tools unless pre-approved via `/permissions` or `permissions.allow` rules", the doc adds: "`AskUserQuestion`, MCP tools marked `requiresUserInteraction`, and connector tools your organization set to `ask` ... are denied even if you've allowed them". So asking the human is itself a permissioned action a mode can switch off. (code.claude.com/docs/en/permissions, 2026-09-05, H)

3. **A second model, not the human, is the graded-autonomy mechanism.** "In auto mode, a second model, the classifier, reviews actions instead of you". The classifier extends to subagents in three steps: "Before a subagent starts, the delegated task description is evaluated, so a dangerous-looking task is blocked at spawn time"; "each of its actions goes through the classifier with the same rules as the parent session, and any `permissionMode` in the subagent's frontmatter is ignored"; "When the subagent finishes, the classifier reviews its full action history; if that return check flags a concern, a security warning is prepended to the subagent's results." (permission-modes, 2026-09-05, H)

4. **Anthropic's published pattern set puts planning after clarification, and names the critique loop as two agents, not one.** "Once the task is clear, agents plan and operate independently, potentially returning to the human for further information or judgement." "In the orchestrator-workers workflow, a central LLM dynamically breaks down tasks, delegates them to worker LLMs, and synthesizes their results." "In the evaluator-optimizer workflow, one LLM call generates a response while another provides evaluation and feedback in a loop." "Agents can then pause for human feedback at checkpoints or when encountering blockers." "It's also common to include stopping conditions (such as a maximum number of iterations) to maintain control". (anthropic.com/engineering/building-effective-agents, 2026-09-05, H)

5. **Self-critique without external feedback is measured as harmful.** "LLMs struggle to self-correct their responses without external feedback, and at times, their performance even degrades after self-correction." (arxiv.org/abs/2310.01798, 2026-09-05, H)

6. **Reflexion's headline number is an external-feedback result, so it is not a counterexample to finding 5.** "Reflexion achieves a 91% pass@1 accuracy on the HumanEval coding benchmark, surpassing the previous state-of-the-art GPT-4 that achieves 80%." The framework reinforces agents "through linguistic feedback" stored in "an episodic memory buffer". (arxiv.org/abs/2303.11366, 2026-09-05, H for the quote; M for my reading that the signal is external, since I fetched the abstract only)

7. **Plan-then-solve is measured against no-plan chain-of-thought.** "our proposed zero-shot prompting consistently outperforms Zero-shot-CoT across all datasets by a large margin, is comparable to or exceeds Zero-shot-Program-of-Thought Prompting, and has comparable performance with 8-shot CoT prompting on the math reasoning problem." Named error classes addressed: "calculation errors, missing-step errors, and semantic misunderstanding errors." (arxiv.org/abs/2305.04091, 2026-09-05, H)

8. **Devin's published guidance is definition-of-done and scope, not method.** "Be as specific as possible. Just as you would provide a detailed spec when asking a coworker to code something, you should do the same with Devin." "Define clear scope, boundaries, and success criteria." "Define what success looks like for each sub-task and optionally set checkpoints within each sub-task." "Tell Devin to test its own work before opening a PR". (docs.devin.ai/essential-guidelines/instructing-devin-effectively, 2026-09-05, H)

9. **Self-check before submit is enforced by cost caps, not by a reflection step, in the GitHub integration.** The documented levers are "`--max-turns`: limit the number of conversation turns", "Set workflow-level timeouts to avoid runaway jobs", and "Use GitHub's concurrency controls to limit parallel runs". (code.claude.com/docs/en/github-actions, 2026-09-05, H)

10. **No shipped system I reached mandates a goal restatement / read-back before work binds.** Linear comes closest and it is an acknowledgment, not a confirmation: agents should "Emit a `thought` activity within 10 seconds to acknowledge the session has begun". (linear.app/developers/agents, 2026-09-05, M — I fetched one page of a multi-page agent guide)

## Findings — ticket schemas and card-state → session

| System | Required fields | State that launches | State that stops | Source |
|---|---|---|---|---|
| Linear agents | App set as **`delegate`**, not assignee: "Assigning an issue to your app now sets it as the `delegate`, not the `assignee`—so humans maintain ownership while agents act on their behalf." `promptContext` carries session context | "Sessions are created automatically when an agent is mentioned or delegated an issue", firing a `created` AgentSessionEvent | UNKNOWN — unassign/stop semantics not on the page I fetched | linear.app/developers/agents, 2026-09-05, H for quotes |
| GitHub Copilot coding agent | Assignee = Copilot: "assign Copilot cloud agent to straightforward issues on your backlog by selecting 'Copilot' as the assignee". No other required field documented on this page | Assignment, the agents panel, Issues, VS Code, "Mentioning `@copilot` in pull request comments", or "Automated workflows triggered by events" | Hard caps: "Maximum execution time of 59 minutes"; "Copilot can only work on one branch at a time and can open exactly one pull request"; "Copilot can only make changes in the repository specified when you start a task" | docs.github.com/en/copilot/concepts/agents/coding-agent/about-coding-agent, 2026-09-05, H |
| Claude Code GitHub Action — interactive | No `prompt` input; a trigger phrase, default `@claude`, "in an issue or pull request comment, in a pull request review, or in the body or title of a newly opened issue" | The mention, gated by two actor checks: "the triggering user must have write access to the repository" and "rejects a bot actor unless you list it in `allowed_bots`" | `--max-turns`, workflow timeout, concurrency; skips drafts and closed PRs | code.claude.com/docs/en/github-actions, 2026-09-05, H |
| Claude Code GitHub Action — automation | A `prompt` input, plain text or a `/skill` invocation | "when the workflow provides a `prompt` input, Claude runs without waiting for a mention, subject only to the checks on who can trigger runs" — any GitHub event including `cron` | Same caps; scheduled workflows run only from the default branch and public-repo schedules disable "after 60 days without repository activity" | same, H |
| Jira · Codex cloud · Cursor · OpenAI Symphony | **UNKNOWN — not fetched** | — | — | call ceiling |

No system I reached carries an explicit **definition-of-ready** gate, a **blocked-reason** enum, a **dependency** field consumed by the agent, or **duplicate detection**. Copilot's "straightforward issues" is the only readiness language, and it is advice.
