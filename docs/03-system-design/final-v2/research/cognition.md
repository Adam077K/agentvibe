## Findings — how shipped systems plan, critique, define done, reflect

1. **Plan mode is a first-class permission mode, not a prompt convention.** "Plan mode tells Claude to research and propose changes without making them. Claude reads files, runs shell commands to explore, and writes a plan, but does not edit your source. Except in sessions with bypass permissions available, edits stay blocked until you approve the plan." Entry: "Enter plan mode by pressing `Shift+Tab` or prefixing a single prompt with `/plan`." (code.claude.com/docs/en/permission-modes, accessed 2026-09-05, confidence H)

2. **`AskUserQuestion` is a real named tool with a privileged status.** In `dontAsk` mode, which "Auto-denies tools unless pre-approved via `/permissions` or `permissions.allow` rules", the doc adds: "`AskUserQuestion`, MCP tools marked `requiresUserInteraction`, and connector tools your organization set to `ask` ... are denied even if you've allowed them". So asking the human is itself a permissioned action a mode can switch off. (code.claude.com/docs/en/permissions, 2026-09-05, H)

3. **A second model, not the human, is the graded-autonomy mechanism.** "In auto mode, a second model, the classifier, reviews actions instead of you". The classifier extends to subagents in three steps: "Before a subagent starts, the delegated task description is evaluated, so a dangerous-looking task is blocked at spawn time"; "each of its actions goes through the classifier with the same rules as the parent session, and any `permissionMode` in the subagent's frontmatter is ignored"; "When the subagent finishes, the classifier reviews its full action history; if that return check flags a concern, a security warning is prepended to the subagent's results." (permission-modes, 2026-09-05, H)

4. **Anthropic's published pattern set puts planning after clarification, and names the critique loop as two agents, not one.** "Once the task is clear, agents plan and operate independently, potentially returning to the human for further information or judgement." "In the orchestrator-workers workflow, a central LLM dynamically breaks down tasks, delegates them to worker LLMs, and synthesizes their results." "In the evaluator-optimizer workflow, one LLM call generates a response while another provides evaluation and feedback in a loop." "Agents can then pause for human feedback at checkpoints or when encountering blockers." "It's also common to include stopping conditions (such as a maximum number of iterations) to maintain control". (anthropic.com/engineering/building-effective-agents, 2026-09-05, H)
