The five ideas, re-read against the direction §0.4

FINAL rested the whole design on five ideas. Three stand unchanged, two move, and none is deleted.

1 · STANDSNothing runs that does not trace to a live Intent with a falsifiable done-test
The roster makes it easier to enforce, not harder. Mechanism: bin/run refuses a brief with no resolving intent id ABSENT
2 · STANDSMethod is never specified. Only the outcome, the constraints and the evidence are
The roster is where this was most at risk. Fourteen named agents carry expertise — a lens, a skill namespace, a model, a grant — never a procedure.
3 · STANDSStanding orders replace approvals. Inside the envelope, silence is permission. There is no approve verb
It hardens from stylistic to load-bearing: a fully autonomous run runs in dontAsk, which denies AskUserQuestion even when allowed. A silent run cannot ask.
4 · MOVESCapacity is one exhaustible pool with a reserve held for the founder
There are two windows per seat — a rolling five-hour and a weekly — so the reserve is per window and per week. A weekly exhaustion is a different event from a five-hour one.
5 · MOVESKnowledge is earned, not curated; memory is mined from what already happened
There is a skill library now. Earned survives with a sharper mechanism: admitted by eval, retired by forced expiry. Mining stays a batch pass over a snapshot, never a live parser.

Neither move overturns an idea; each replaces a belief with a mechanism. A founder overrule made both sharper than the original, which is the argument for not re-litigating them.

A day with it §0.5

FINAL's day ran on a clock. The plan forbids schedules and durations, so this is the same day re-anchored on the page the founder is looking at and the agent doing the work.

The phone, first thing
Nothing, unless a wake-me line fired. If one did: one line.
The Watch slept through everything that did not qualify. Three interruptions a day, and a channel whose acted-on rate falls is demoted below its threshold.
The briefing
One page the founder opens, so it is never an interruption. What moved, with the evidence; the raw work biggest first — the rendered page, the played video, the diff, the email that would go out, staged and unsent; two whiches, both built; what could not be checked, named; what it cost per venture and per window.
writer staged the email and never held the key. designer's anchor is the screenshot judged against a named target, not its own description. Every cost row taps through to its run.
Mission control, page 2
The Operator and its children: who is working, who is sleeping, what each is doing on the current task.
One level of teammates is visible because the runtime ships no nested teams; the deeper tree is subagents.
A tap on an agent
A terminal opens on the Mac and the founder is inside that session.
"remember each agent or each session that we are opening in the mission control or any other surface, it's directly opening it in the terminal in my Mac because everything is run on it" (FOUNDER). The mechanism is the documented tmux CLI (§15).
Mission control, page 4 — the board
Tickets, PRs and a timeline. The founder drags a card into working on it.
The drag launches a session with a team of agents and hands it the task. Nothing in the world does this — every board-to-session project found maps one task to one agent, so this part is ours to build.
The Floor
A terminal, one agent, the same memory and the same envelope. The founder's own browser and own send button are here and nowhere else.
The system goes sterile: nothing interrupts, nothing new is dispatched on the founder's window, the venture under their hands is held whole. When they leave, the queue is one paragraph.
A which
Two options, both already built, and the cost of each. One tap.
There is no approve verb anywhere in the system. Outside the envelope, the system builds both and asks which.
The night
Nothing. The founder is asleep.
Obligations first, before any goal. Then, under each driven venture's ceiling, runs are born with a brief, work however they like, are checked by something outside the model, hand back seven fields, and die. Routine work burns the Gemini window. A fully autonomous run cannot ask.
Dawn
The briefing again.
The curator has already run: delta-only writes, one writer, an index loaded at start and topic files on demand.

§10

Codex and Claude Code, from day one

Four options were judged against a measured defect rather than a preference. One was chosen.

§10.1 · the chosen shapeA third program drives bothOne launcher, bin/run, composes argv. Nothing else may
CHOSENbin/run ABSENT

Each vendor documents a headless invocation, a session id, resume, an instructions file, a SKILL.md bundle and MCP. A provider outage or a defect becomes a routing change, not a rewrite.

It is a consequence, not a taste: if two things compose argv, two things define what a run may touch, and the guarantee that a checker cannot edit what it judges becomes an agreement between them.

Rejected
Claude Code drives Codex from Bash — exactly the shape openai/codex#19945 breaks. The script -qfc cure is "incompatible with normal background / parallel job execution", which is what a crew is
Rejected
Codex drives Claude — no documented mechanism in either direction, and Codex is not installed
Folded in
Hybrid — the Floor is interactive Claude Code and always was; the founder may run Codex by hand there
The seam
Only the policy tier differs between runtimes. Anthropic's managed settings outrank argv; OpenAI's requirements.toml outranks every flag; Google has a Policy Engine
§10.2 · day oneCodex's position: a checker on a prepared diffForeground, stdout redirected to a file, inheriting the parent shell's TTY
codex NOT INSTALLED

The position is narrow because a measured defect makes it narrow, not because Codex is distrusted.

The cost, stated once and not re-litigated: one foreground slot is not parallel, so Codex is not a night lane yet. That is the whole price of admitting it on day one, and it buys a second model family on the one move where family independence pays for itself.

openai/codex#19945, read 2026-09-05: "codex exec silently crashes with no output when stdio is detached from TTY (0.124.0+)", opened 2026-04-28. Open 130 days with no comments and no maintainer reply. The process produces no error, no panic, no log entry — just an empty result. Piping through tee or tail does not resolve it. A silent empty result is the worst failure shape there is.

§7

Skills

The founder overruled FINAL's refusal of a library. Two tiles: what the library is, and the creator that makes new ones.

§7.1 · the library planTwo directories, one source of truthThe container is the open SKILL.md standard, fetched 2026-09-05. Its published limits are the file's limits
bulk import BLOCKED

Claude Code reads .claude/skills/. Codex and Gemini CLI both read .agents/skills/, and Codex does not read .codex/skills. So there are two directories and one source of truth: Markdown is the source, and both directories are generated from it.

Collisions are not merged. Codex states it plainly: if two skills share a name, both appear in skill selectors. A drifted generated copy does not error; it appears twice with different bodies. So the generator is the only writer of either directory, and nothing hand-edits them.

Limits
name ≤ 64 chars and must match the parent directory · description ≤ 1024 · metadata ~100 tokens loaded at startup for all skills · instructions under 5,000 tokens recommended · body under 500 lines
Blocked on
The upstream advertises 2,111+ skills, MIT on the code — but a separate LICENSE-CONTENT file exists there and was not fetched. No bulk vendoring until it is read. One fetch clears it
UNVERIFIED
this branch's SKILLS_SOURCE.md names npx antigravity-awesome-skills; the upstream now advertises npx agentic-awesome-skills. Whether the old name still resolves is unverified
Read the sources for what they are
anthropics/skills is 19 directories with no root LICENSE file · wshobson/agents is MIT, read from LICENSE · both VoltAgent lists are indexes of links, MIT unverified · the spec repo's licence is UNKNOWN, not fetched
§7.5 · the skill creatorbin/skill — a program, not a fifteenth agentIt holds no model. It sequences four moves, each performed by an agent under that agent's own grant
ABSENT

"we need a skill creator of skill, which, you know, we will research a task or a mission and, like, to break it down two steps and to give it to the agents." (FOUNDER)

1 · scout
answers the bounded question of how the field actually does this. URL, quote and access date on every claim; check-citations.mjs blocks on a dead one
2 · product
states the done-test the skill is supposed to make reachable — falsifiable by someone who did not do the work, or the store check refuses it
3 · curator
writes the artifact into one of the four admissible bodies and proposes its valid_until
4 · eval
runs with-skill against baseline. A candidate that does not beat baseline is not admitted, and the negative is written to the negatives store rather than discarded — the failure is the cheapest thing the run produced
Expiry
when valid_until falls due, exactly one disposition: refresh, deprecate, or waive with a new date

The scout fan-out inside move 1 is the one place parallelism is earned: four scouts asking four independent questions do not need each other's context.
