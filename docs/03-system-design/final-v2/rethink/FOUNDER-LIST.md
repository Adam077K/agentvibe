## Wing 1 — Model Layer
Primary + secondary LLM selection (cost/speed/context tradeoffs) · Abstraction layer to swap models without rewriting code · Prompt engineering, versioning, and prompt registry · Fallback policy between models on failure/rate-limit · Cost control per model call, with daily/monthly budget

## Wing 2 — Planning & Cognitive Layer
Planner engine converting intent into sub-tasks · Cognitive layer evaluating possible outcomes before acting · Self-reflection / self-critique before critical actions · Task decomposition logic for splitting work across agents · Prioritization mechanism for parallel tasks

## Wing 3 — Multi-Agent Orchestration
Orchestration model (graphs / role-based crews / hierarchical trees / conversational loops) · Agent registry (profile per agent documenting capabilities and role) · Task routing (engine deciding which agent gets which task) · Agent-to-agent protocol (A2A) · MCP / external tools · Guardrails · Human-in-the-loop

## Wing 4 — Memory & State
Short-term memory per task run · Long-term memory persisting across sessions · Episodic memory for debugging and learning · Per-agent/team/global memory permission separation · Provenance tags: source, owner, ACL on every memory item · Redaction/sanitization before sharing between agents · State persistence surviving failures (resume, not restart)

## Wing 5 — Tool & Integration Layer
Tool layer for API calls, file access, code, databases · Vector database + embeddings for semantic search/RAG · GitHub/CI-CD integration for automated code writing/testing/merging · CRM, project management, and payments integrations · Infra layer: hosting, edge functions, serverless compute

## Wing 6 — Security & Governance
RBAC for every agent and human on the team · Full audit logging of every action, decision, tool call · Escalation paths for human intervention on anomalies · Secrets management and API key security · Governance framework defining ownership per layer

## Wing 7 — Observability & Evaluation
Real-time dashboards tracking agent runs · Alerting for failures, infinite loops, cost overruns · Evaluation system checking output against standards · Structured logs of full decision chains · KPIs: efficiency, quality, business impact

## Wing 8 — Interface Layer
Streaming chat/UI for real-time interaction · Internal dashboard for the dev team · Public/private API for external product integration · User and developer documentation

## Wing 9 — Human Org Layer
Product/Founder owner — strategy, KPIs, prioritization · Tech lead/Architect — cross-layer compatibility · Agent engineer — builds/tunes agents and prompts · Security/compliance owner — guardrails and audit · Ops/growth owner — CRM, sales, operational tools · QA/evaluation owner — quality metrics and testing

## Ensuring all parts work together
Define clear contracts between layers (fixed input/output formats) · Build layer by layer, not everything at once · Run a 2–3 week assessment mapping existing workflows before automating more · Pilot on one team/process for 2–4 weeks, measure against baseline, then expand · Avoid tool sprawl: every new tool should replace an old one, not stack on it

## Handoff prompt template for the next team
System purpose (one sentence) · Wing map (all 9 wings, what exists vs missing in each) · Relevant contacts (owner of each wing) · Current state (which layers are built, in progress, or only on paper) · Open decisions (unresolved, with both sides' reasoning) · Open-mindedness instruction (rethink, envision, improve, not just continue) · Success criteria (measurable KPIs defining "worked" vs "didn't")
