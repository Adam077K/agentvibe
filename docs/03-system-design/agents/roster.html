The premise held

Seven rests on one claim: a capability grant exists in exactly one place — agent-file frontmatter. A SKILL.md also carries allowed-tools, which looked like a second channel and would have cut the roster toward five. It is not. The binary's own schema resolves it: that field subtracts, it never grants. The number survives — and the field turns out to be a live hazard in the opposite direction.

The rule

Why the count is what it is

This runtime prices denials and grants differently. A capability denial is settable at a dispatch, and on a skill. A capability grant exists in one place only: the agent file.

The binary describes allowed-tools on a skill as "tools available to the model while this file is active" — the same wording as tools: on an agent, the field already proven to subtract with the strongest evidence in the corpus (sourcer: 0 Bash calls in 284; reviewer: 0 Write and 0 Edit across 4,373). So the floor is the number of capability grant-classes that must not share a container: read the public web, see a rendered surface, read the business's own systems of record, act irreversibly on the world. This repo holds one.

A distinction that reassigned four skills

Read their own descriptions: web-design-guidelines is "review UI code for compliance". design-audit "conducts systematic visual audits". 12-principles-of-animation "audits animation code, outputs file:line findings". These are judging postures, not producing ones — and attaching them to the producer put a judge inside the thing being judged. They move to reviewer, where the same knowledge does work that binds.

Three skills are broken in ways nothing currently checks

web-design-guidelines — its entire procedure is four WebFetch calls to a raw GitHub URL, and neither designer nor reviewer holds WebFetch. A pointer to a page no assigned container can open.

pitch-deck-visuals declares allowed-tools: Bash(belt *) for a CLI that is not on this machine — a capability declaration nothing backs, which is exactly what the linter refuses for agents, inside a file class the linter never reads.

impeccable declares two Bash(...) forms and no read tools at all. Now that allowed-tools is known to subtract, attaching it to designer would strip the browser grant that container exists for. Strip the line first.

The design process

A per-project structure, built so an agent that did not create it can trust it six weeks later

design/                    ← repo root, a peer of docs/
  INDEX.md                 ← the only file designer must read to know what is here
  system/                  ← the rules. rule first, reasoning after
    principles.md          ←   what this product looks like, and why
    palette.md             ←   colour, in OKLCH, with the meaning of each token
    type.md · space.md · motion.md
    audience.md            ←   DEMOGRAPHICS. who this is for, and what that forbids
  tokens/
    tokens.json            ← AUTHORED. the source of truth. one flat map
    tokens.css · tokens.ts ← GENERATED. never hand-edited
    contrast.md            ← GENERATED. every pair, computed, dated
  references/
    <slug>/SOURCE.yml      ←   url · access_date · captured_by · attribution · expires
           capture.png
           notes.md        ←   what we take, what we reject, and why
    inbox/                 ←   drop zone; a script slugs and files whatever lands here
  visuals/                 ← OUTPUT. marketing visuals, OG images, deck art, social cards
  decisions/               ← NNN-<slug>.md, same shape as an ADR
  captures/                ← GITIGNORED. the perception loop's output. never committed

Every part is labelled authored or generated, so nothing rots quietly and no one hand-edits a derived file. References carry attribution and an expiry. The inbox/ is how visual references get in — drop them, or send an agent to fetch them, and a script files them with their source.

MCP servers

Every agent gets every server — and the dangerous ones are denied per agent

The recommendation gives you the instruction almost verbatim: every engine's tools: names every server, with a server-level denial in the same file for the small set that must not be universal. One line per file. Three options are specified in full — strictest, recommended, and the literal instruction — so the choice is yours with the cost visible.

Why class C is denied rather than granted

A sourcer that ingests attacker-controllable web text while holding a secrets tool and an outbound mail tool is a one-hop exfiltration chain with a channel attached: fetch a page, the page's text instructs a call, the answer leaves by the next one. A builder holding deploy can make its own deploy pass — the single failure the whole review apparatus exists to prevent.

And claude-in-chrome is unlike the others: its credential is your own logged-in browser. There is no key to revoke, because the key is a person.

Two questions, answered

The ones you asked directly

Does each agent get its own worktree?

One per dispatch, not one per agent.

The unit of isolation is the work slice, which already carries an id. Two builders running at once get two worktrees; the same builder dispatched twice gets two.

EnterWorktree and ExitWorktree are live in this CLI, and ExitWorktree refuses to remove a tree holding uncommitted or unmerged work unless discarding is explicit — runtime enforcement where we currently have prose.

Who owns scheduled work and checkups?

A script and a real clock. No agent.

instrument is a callee of the clock, never its owner: 365 unattended credentialed runs a year, for work a script does deterministically, is the largest avoidable credential exposure in the design. Not operator, because a timer is not an approver. Not the orchestrator, whose defining property is ending a turn on a human that a scheduled run does not have.

The clock is launchd — it runs a window missed while the laptop slept. The existing Actions schedule stays as a second, independent clock, because two clocks that fail for different reasons is the point.

Still open

One resolved, three that need an experiment

Does allowed-tools in a skill grant capability? — Resolved

It subtracts. The binary describes it as "tools available to the model while this file is active" — the same wording as the agent field already proven to subtract. The roster number survives. The earlier spec called it "decoration"; right premise, dangerous conclusion. The action changes from strip it eventually, it does nothing to strip it before attaching, because it does something.

Settled from the installed binary — no probe needed

What actually stops a run?

maxTurns does not bind, stop reasons are recorded nowhere, and the silent-empty-return failure has been hit nine or more times — including three times by subagents during the sessions that produced these specs, each going idle reporting "available" while incomplete.

Probe: add stop_reason to the turn indexer — one field — reindex the corpus, cross-tabulate against runs that returned nothing. The data already exists in every transcript. Nothing reads it.

Does the design pass produce a better product?

Twenty seeded rendered defects; a browser-holding reviewer against a source-reading one. This probe governs the browser grant, and therefore whether designer is a container at all.

Unrun · governs the grant

Do eight skills beat three?

Nobody in the field has an A/B harness for skill sets, any more than for rosters. Anthropic's skill-creator ships the instrument — evals, an isolated subagent per case, grading, and a benchmark comparing with-X against without-X. Point it at the list one skill at a time. It can kill any of the eight as easily as vindicate it, and either result is worth having.

Per-skill · the only honest test of a knowledge base

Provenance. Six planners on Opus across three rounds, each specifying its agents across 17 dimensions — the ten named in the brief, plus effort, return contract, stop behaviour, autonomy and escalation, credentials and network boundary, observability, and QA of the agent definition itself.

Conventions were inherited rather than invented — BMAD-METHOD, YC's QM, GitHub Spec Kit, Agent OS, GSD, obra/superpowers, Cloudflare's agents, anthropics/skills, and the Oczkowski and Krehel design packs — each recorded with what was taken, what was rejected, and why. Where the field disagreed with what was measured in this runtime, the measurement won.
