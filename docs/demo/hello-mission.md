# Trusted projects — summary

Mission Control shells out to git and project scripts, and on 2026-08-14 that produced three confirmed RCEs reachable from any repository discovered under ~/VibeCoding that the user did not write. In response, discovery no longer implies trust: a project must be explicitly added to an allowlist before its code can be executed. The list lives at ~/.warroom/trusted-projects, an exact-path-equality allowlist with no globs or prefixes, kept outside the repository because mission-control itself is one of the governed directories and because paths are machine-specific. It's managed via `bun run trust` (list/seed/add/remove) and is never written by the server itself — only by that CLI — so a trust decision can't be made silently at boot. On a machine with no list, nothing is trusted but nothing is hidden either; every discovered project still shows with its exclusion reason. This is explicitly a mitigation, not a fix: an allowlisted project that later turns hostile is still full RCE, and the `/api/fleet` route's `git worktree list` still runs against every discovered project regardless of trust status.
